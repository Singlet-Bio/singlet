## 2. Download path

**I/O stage today** (O `scripts/atlas_rerun/stages.py`):

| step | lines | bound by | needs | measured |
|---|---|---|---|---|
| head stream, 1 M pairs per run | 175-189 | network latency (remote VDB, 0.065 M reads/s) | singlet | 9-28 s; one 454 s fallback. OOM at 16 GB twice; #47 fixes it (19.1 → 1.18 GB) |
| `screen-runs` | 194, 242 | light CPU | singlet | not timed |
| `prefetch` | 218-239 | network | sra-tools only | ~38 MB/s per stream; 12-711 s per sample |
| decode `.sra` → `.1fq` | 229 | CPU, 1 core, ~1 M pairs/s | singlet + ncbi-vdb | 38 s at 61.5 M pairs, 102 s at 111.6 M, 310 s at 263 M. I/O peak 3.4 GB |
| pool runs (decode + encode) | 306-336 | CPU and memory | singlet | 670 s at 122 M pairs; hit the 16 GB limit |

**Network-only unit.** Fetch each kept run's `.sra` with `prefetch` or `curl` from `sra-pub-run-odp.s3.amazonaws.com/sra/<r>/<r>`, verify it, write a manifest, emit an event. No singlet binary is needed.

**What compute must then do.** Compute cannot start from `.sra` directly:
- #47's multi-run input takes `.1fq` only (P `singlet.cpp:2762-2763, 2935`; `include/singlet/fq/concat.h`);
- `--sra` is deprecated and single-run (`singlet.cpp:2978-2982`).

The compute node therefore runs, per run, `singlet download <run>.sra`, then `screen-runs`, then `singlet --runs-dir D --run-screen screen.json`.
- **Concat vs pool:** concat took 0.5 s for 4 runs, against 670 s for pooling.
- **Not byte-identical to pooled:** ambient rho 0.367 vs 0.370, which is the barcode-order bug.
- **Mismatched runs:** `concat.h:109-127` rejects runs whose read lengths or flags differ, so those samples need a fallback.
- **Decode cost:** about 2% of a median sample's compute (I). An Anvil node has 16 cores outside its 112 four-thread slots (`common.py:33`, `config.json:88`), so decode costs about 0 extra SU.

**Bytes.**
- **Total:** 1.9 PB including the +20% retry margin (`cost_model_v2.py:31,54-57`). Raw is about 1.58 PB, ≈22 GB per sample and ~73 B per pair (I).
- **Per-sample sizes:** the distribution is not recorded. ENA `sra_bytes` is fetched (`fetch_runinfo.py:32,97`) but not used by `orchestrator.py plan` (97-130).
- **`.1fq` vs `.sra`:** ~2.8× smaller with `--quality none`, the `download` default (P `singlet.cpp:424`; estimate in `docs/format-1fq.md:867-872`; never measured).
- **SRA Lite:** nothing requests it. NCBI states about −60% bytes for runs that have it.
  - It can be selected with `prefetch --eliminate-quals` (sra-tools ≥ 3.1.0) or the vdb-config "prefer SRA Lite" setting.
  - Since `.1fq` already drops qualities, Lite is probably output-neutral for counts.
  - Open question: the mtDNA and SNP callers use base quality (research-beta.md bug 4).

**Anvil login nodes.**
- **Measured on login00:** per-user cgroup CPU quota 2 cores (`cpu.cfs_quota_us` 200000) and memory 12 GiB.
- **Hardware:** 8 login nodes, 32 cores / 512 GB each.
- **Policy:** login nodes are for "light pre- and post-processing only"; the front-end policy says heavy processes may be killed without warning. No page explicitly allows long downloads.
- **Precedent:** the earlier v2 campaign ran a login-node download daemon with ≤4 concurrent downloads (`singlet-website-anvil/docs/ANVIL-NEW-STUDIES.md:100`). A heavy bundle step on login06 hit load 144 and was aborted (:104).
- **Transfer nodes:** Anvil publishes no separate data-transfer node; Globus is the documented path for site-to-site moves.
- **Tools:** the `aws-cli/2.4.15` module exists. sra-tools are not on PATH and must be installed under `$PROJECT`.
- **Scratch:** 100 TB / 1,048,576 files; purge at 30 days by **access time**, with no warning. Circumventing the purge is an acceptable-use violation.

**Orchestrator changes** for a login-node fetcher:
- **Inbox writer:** the fetcher only calls `common.emit` (`common.py:218-238`), which works from any host.
- **Tickets:** the controller issues `fetchq/` tickets in place of the I/O array (`orchestrator.py:511-533`).
- **Liveness:** `expected_job` (286-295) only knows Slurm jobs, so add a fetcher heartbeat. Map fetcher loss to `released`, not `lost`: `lost` counts a failure and `retry_max` is 1 (337-346).
- **Atomic files:** use `.part` files and a rename.
- **Node pickup** (536-538) is unchanged.
- **Staging:** the cap is 40 TB (`config.json:80`). One busy node consumes ~110-230 MB/s of SRA, so 40 TB ≈ 12 h of 4 nodes.

**Clipper.**
- **Ceiling:** 125-160 MB/s from NCBI and 116 MB/s from S3, whatever the stream count. Still untested: a 24 h 32-stream test and a GVSU Science-DMZ path.
- **Head screen:** about 0.4% of a median sample's bytes; it costs latency, not bandwidth.

## 3. Acceleration

**Stage profile at 4 threads** (seconds, % of wall):

| stage | ~66 M PBMC (M; idle node, no screen, 845 s) | ~110 M (M; smoke, shared node, screen on, 2,196 s) | ~260 M (M; smoke, 5,097 s) |
|---|---|---|---|
| STAR mapping + unsorted BAM bins | 515 (61%) | 630 (29%) | 2,820 (55%) |
| **BAM sort (disk)** | ~145 (17%) | **1,080 (49%)** | 990 (19%) |
| index, CB-tag refresh, pileup | 85 (10%) | rest 486 (22%) | rest 1,287 (25%, I) |
| genome / reference load, export | 58 (7%) | | |
| non-host screen | +94 s (+10%) campaign binary; +300 s (+27%) older binary | | |

- **5′ sample at 122 M pairs:** sort 2,760 s (60%) of 4,570 s.
- **Amdahl fit** of the 4/8/16-thread runs: S = 358 s serial plus P = 2,184 s parallel. About 40% of the 4-thread wall does not scale.
- **Packing:** four-way packing costs 1.28×, against the model's 1.15.
- **Cost model:** wall = 300 + 12.79·U s (U = M pairs). The fixed 300 s is overstated; it is closer to 130 s.

**Is the sorted BAM needed?**
- It is not kept: `stages.py:359` excludes it, and P `singlet.cpp:7801` unlinks it after pileup.
- **Readers:**
  - `sam_index_build3` (7167);
  - the CB-tag refresh scan (7731);
  - `run_parallel` (7777; `pileup_engine.h:1176`);
  - the strand re-run (7789) and strand probe (`pileup_engine.h:1769`).
- All modalities accumulate in that one pass (`process_read_parallel`, :2898).
- **Why STAR sorts:** STAR fills CB/UB only at sort time with CB_UMI_Simple (`ParametersSolo.cpp:410-418`, `BAMbinSortByCoordinate.cpp:70`). CB_samTagOut is exact-match only.
- **Streaming path:** a streaming `run()` exists (`--no-parallel-pileup`, :6974), tested only on a synthetic BAM.
- **Route to identical output (I):**
  - keep CB_UMI_Simple and CellReads.stats;
  - emit CR/UR;
  - replicate `1MM_multi_Nbase_pseudocounts` in the pileup from pass-1 exact counts;
  - take strand from the header and run screen.

**Non-host screen.**
- **Algorithm:** k = 21, w = 11 minimizer sketches. The viral, bacterial and fungal indexes are ~25 GB on disk and ~35 GB resident per job.
- **Reads:** every STAR-unmapped cDNA read, capped at the first 20 M.
- **Scan:** a serial merge-scan of each whole DB (`min_sketch.h:282`), so the cost is O(DB), not O(reads).
- **Per-job loading:** each job zero-fills and copies 25-35 GB (`MinSketchIndex::merge`, :1439, :1454). The "/dev/shm gives no gain" test still copied to the heap, so mmap was never tested.
- **Cost model:** it charges 4.5 s/M, about 150k core-h. The real cost is probably 10-47k core-h (I).
- **`nonhost_reads.fq`:** written whenever a raw kingdom fraction exceeds 1%, then discarded.

**Too-short reads.**
- 4.1% of reads and 19% of mapping on 3′; 7.4% and 55% on 5′.
- An exact early exit was built twice (cd2192c7, 503df7dd) and saved nothing: the cost is in the seed search, before any bound exists.
- Dropped.

**Genome and packing.**
- Campaign jobs use a private genome and 96 GB, so a 512 GB Clipper node fits 5 jobs.
- RSS is 23 GB without the screen and 53 GB with it.
- With a shared genome and a mapped screen index, ~16 jobs fit in ~350 GB (I).
- A shared genome gets no huge pages: +5% wall.

**Work done twice:**
- pooling: decode, encode, decode;
- `.1fq` pass 1: a serial full decode, then a second decode for STAR;
- BAM: written, sorted, rewritten, indexed, then scanned twice;
- counting: STARsolo counts and the pileup recounts;
- head screen: streamed, then prefetched again;
- unmapped mate1: read 3×, plus the discarded dump.

**Ranked changes:**

## 4. .s1 alignment with Alpha

**Contract** (A `docs/format-s1.md:22-34`; W `workers/data/src/handler.ts:98-110`).
- **Keys:**
  - required: `s1/s/<GSM>/<d16>.s1` (immutable), `s1/m/<GSE>.json` (mutable, written last), `s1/ref/<id>.pack` plus `index.json`;
  - optional: `s1/a/<GSM>/<d16>.parquet` label sidecar, `s1/cidx/*`, `s1/cells/<GSE>.cells`, `s1/ledger/<GSE>.jsonl`.
- **Cells table, required:** `barcode, called, n_umi_exon, n_umi_intron, n_feat_exon, n_feat_intron`.
- **Cells table, optional:** `called_ed`, `called_ed_fdr`, and 14 label columns.
- **Manifest, optional fields:**
  - `release_policy{name,version,omitted_layers}`;
  - per-sample `provenance`, `junction_support`, `annotations`.
  - None of these is in `format-s1.md` §7.
- **D1:** `s1_study`, `s1_sample`, `s1_migration`, `s1_flags`, plus the label and ontology tables (W schema 032, 033, 038, 039).

**No pipeline → .s1 path.**
- The migrator reads only `LegacyBundle` (A `legacy.py:312`; `migrate_bundle` opens it at `migrate.py:1211`).
- The only pipeline route, `scripts/s1_publish.py:54-88`, zips `results/<GSM>/out/` into a throwaway legacy bundle. It does not match the orchestrator layout: `out/<GSE>/<GSM>/`, a split `private/`, and `run.log`, `screen.json` and `MANIFEST.sha256` mixed in.
- **Needed:**
  - a `PipelineDirBundle`;
  - a study-file writer (`manifest.json`, `study_meta.json`, `feature_vocab.json`);
  - `Options.sample_facts` from `handoff/<GSE>.json`;
  - `called_ed` taken from `cell_calls.tsv`;
  - `ambiguous_counts.1pz` added to the modality lists.

**Release policy.** It is fixed and named "alpha" (`policy.py:36, 97`; `--alpha-policy` at `s1_campaign.py:2445`). Beta needs a per-layer state (public, preview, omit or private) generated from the `bench/public` results, with `singlet.commit` equal to the engine commit.

The `private/*` rule exists in `P:python/singlet/_restricted.py:47`, but is missing in two places:
- A's `s1/policy.py`;
- W `functions/_shared/restricted.ts:36`.

**Channels.** No release, channel or version concept exists. If a Beta manifest replaced an Alpha one:
- `rev` flips and the old-rev rows are deleted;
- `alpha_exclusions` hides samples that Beta fixed;
- saved cohorts and `col` indices break, because cells are re-called;
- the sidecar `cells_digest` and cidx ordinals mismatch;
- storage doubles, because there is no GC.

So use the isolated Beta stack (Zach's decision of 2026-10-27, in rollout-plan.md §0).

**Labels.**
- `label_sample` (`labels_step.py:193`) sums exon + intron, so it runs on Beta counts unchanged.
- Its accuracies were measured on Alpha counts. Revalidate them and give Beta a new `annot_version`.
- It labels the knee `called`, not `called_ed`. Choose which set to label.
- **Ancestry depth tables:** Beta writes them to `private/donor/` (P `export.h:1572-1574`). The labeller only finds them inside `restricted/<GSE>/<GSE>.restricted.singlet` in bucket `singlet-restricted` (`s1_campaign.py:1599-1638`), so pack the private tree there.

**Naming debt on P.**
- **`called_v2`:**
  - C++ header and namespace;
  - `cell_calls.tsv` columns `called_v2` and `fdr`;
  - the CLI `--cell-caller called_v2`;
  - golden vectors and tests;
  - docs: 73 files in all.
- **Provenance:** `cell_caller:"called_v2"`. `genome_dir` and `gtf` hold cluster paths (`run_provenance.h:225-227`), so allowlist fields before they reach a manifest.
- **The whole `python/singlet/v2/` tree:** `.s2`, `V2*`, `SINGLET_V2_`, the `singlet-v2` strings and the `v2/` prefixes.
