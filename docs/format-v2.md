# Singlet v2 data format (`.s2` sample objects, `pz2` matrices, packs, manifests)

Status: DRAFT 1 (2026-10-22), owned by the v2 migration (`bench/compression/PROPOSAL.md`, `docs/v2-migration.md`). Sections 4.1, 4.2, 4.5, 5.1
and 5.2 (written by the codec agent, W1) describe exactly what `include/singlet/pz2/` does and were checked against it; the C++ code is
the reference implementation (header 4.1 is 256 bytes: the original field list summed to 180, not 160, and the codec parameters needed room).
All integers are little-endian. "digest16" = first 16 bytes of SHA-256. Text is UTF-8.

## 1. Goals and invariants

1. **Bit-equivalence.** Every member of a legacy `.singlet` bundle is reproduced exactly from v2: matrices as identical canonical CSC
   triples (indptr, indices, data, row names, column names, key/values), every other member as identical bytes. Each component is
   either regenerated by a pinned recipe or stored ("verify-or-store"): the migration tries the recipe, compares bytes, and stores the
   original when they differ. A v2 file therefore never depends on a recipe that was not verified on that very sample.
2. **Nothing derivable is stored** when the recipe verifies: row names (packs), barcodes (whitelists), permutations, column pointers,
   column sums, filtered matrices, PSI, ambient profiles, QC tables computable from counts.
3. **Random access to cells.** Matrices are column (cell) chunked with a fixed-width chunk index at a known offset; any column range is
   decodable from its chunks alone. One HTTP range request per contiguous run of chunks.
4. **Immutable, content-addressed objects.** A sample object's key contains its digest; rewriting creates a new key. Only study manifests
   are mutable. Cached offsets can never point into a different file.
5. **Fast, portable decode.** Integer-only, byte-identical results on scalar, AVX2, AVX-512 (and future NEON) paths; runtime dispatch.

## 3. Sample object `.s2`

```
offset 0   FileHeader (64 bytes)
           magic        8   "SINGLET2"
           version      u16 = 1
           flags        u16 = 0
           n_members    u32
           table_off    u64  (= 64)
           table_len    u64
           file_len     u64
           sample_id    16   ASCII GSM id, NUL padded
           reserved     8    zero
offset 64  MemberTable  (table_len bytes): n_members entries, each
           name_len u16, name (UTF-8, the legacy member file name, e.g. "exon_counts.1pz", or a v2 name such as "cells")
           kind u8       1 = pz2 matrix, 2 = cells table, 3 = stored blob (zstd), 4 = derived (recipe), 5 = raw (stored as is)
           flags u8      bit0: legacy member (regenerates a member of the legacy bundle); bit1: required for to_anndata
           off u64, len u64      byte range of the member body inside this object (0, 0 for kind 4)
           out_len u64           byte length of the regenerated legacy member (kind 3/4/5) or 0
           crc32 u32             CRC-32 (ISO 3309) of the regenerated legacy bytes for kinds 3/4/5 (equals the legacy ZIP CRC); 0 for 1/2
           digest 16             digest16 of the canonical content (section 4.6 for matrices, section 5 for tables, regenerated bytes otherwise)
           meta_len u32, meta    JSON object: recipe id and parameters (kind 4), zstd level (kind 3), legacy codec facts, etc.
           Member bodies follow, each starting at a multiple of 64.
```

A client normally learns member offsets from the study manifest and fetches exactly one range per member or chunk run; the header
and table make the object self-describing offline.

## 4. Matrix member `pz2` (kind 1)

### 4.1 Header (fixed 256 bytes)

All offsets are byte offsets from the start of the member; integers are little-endian.

| offset | size | field | notes |
|---|---|---|---|
| 0 | 4 | magic | `"PZ2M"` |
| 4 | 2 | version | 1 |
| 6 | 2 | codec | 1 = lane rANS (fast, section 5.1), 2 = generic gaps + zstd (any size, section 5.2) |
| 8 | 4 | m | rows (features) |
| 12 | 4 | n | columns (barcodes) |
| 16 | 8 | nnz | stored non-zeros (explicit zero values count) |
| 24 | 1 | value_type | 1 = u8, 2 = u16, 3 = u32, 4 = f32. For 1..3 this is the legacy `.1pz` `vt_code` (a legacy file may store u32 although all values are small; the migration keeps the legacy code). f32 values are stored as u32 bit patterns (see `flags`) |
| 25 | 1 | row_order | 0 = canonical row ids (codec 2); 1 = class order (codec 1, section 4.3) |
| 26 | 1 | classes_per_octave | 0..8; 0 = exact frequency rank. Meaningful for codec 1 only |
| 27 | 1 | flags | bit 0: value_type 4 coded as integers (every value is a non-negative integer below 2^24 whose float bit pattern round-trips; `-0.0` and NaN never qualify); other bits zero |
| 28 | 4 | chunk_cols | nominal maximum columns per chunk (a chunk may be narrower; see 4.2) |
| 32 | 4 | n_chunks | |
| 36 | 1 | lanes | codec 1: 16, 32 or 64 (written as given for codec 2 and ignored) |
| 37 | 1 | prob_bits | codec 1: precision of the gap/flag tables, 8..12 |
| 38 | 1 | value_prob_bits | codec 1: precision of the residual tables, 8..12 |
| 39 | 1 | ctx_kind | codec 1: context configuration 0..4 (section 5.1) |
| 40 | 8 | row_names_id | pack id prefix (first 8 bytes of the pack digest16) when `rows_kind` is 1 or 2; otherwise zero |
| 48 | 8 | col_names_id | pack id prefix when `cols_kind` is 1 or 2; the ASCII bytes `"CELLS\0\0\0"` when `cols_kind` is 3; otherwise zero |
| 56 | 16 | digest | digest16 of the canonical CSC (section 4.6), or zero when the writer did not compute it |
| 72 | 112 | section table | 7 x {u64 off, u64 len}, in the order rows, cols, kv, tables, chunk_index, chunks, extra; offsets relative to the member start |
| 184 | 8 | total_len | byte length of the whole member |
| 192 | 1 | rows_kind | names kind of the rows (below); 3 is invalid for rows |
| 193 | 1 | cols_kind | names kind of the columns |
| 194 | 58 | reserved | zero |
| 252 | 4 | header_crc32 | CRC-32 (ISO 3309, as zlib) of bytes 0..251 |

Names kinds: 0 `Inline` (names stored in the member), 1 `Pack` (names equal the pack's list, in pack order; nothing stored), 2 `PackSubset` (name `i` is entry `index[i]` of the pack; the index list is stored), 3 `Cells` (columns only: the names are the barcode column of the sample `cells` table; nothing stored), 4 `None` (the matrix has no names; the canonical digest then hashes zero names).

A reader must reject a header whose magic, version, CRC, codec or names kinds are invalid, whose sections do not lie inside `[256, total_len)`, whose `chunk_index` length is not `(n_chunks + 1) * 24`, or that declares codec 1 with `m >= 2^21`.

### 4.2 Sections

Physical order (sections are packed back to back, no padding, no alignment; a section of length 0 has `off` equal to the position it would have had):

```
header (256) | chunk_index | tables | rows | chunks | cols | kv | extra
```

`header + chunk_index + tables + rows` is the **prefix** (`prefix_len = rows.off + rows.len`). It is everything needed to plan and decode any column range; a remote client fetches the first 64 KB (or the prefix length from the header, whichever is larger) and then one range per run of chunks. `cols`, `kv` and `extra` are needed only for names and key/values.

`STREAM` below means `u32 raw_len, u32 zstd_len, zstd frame`; `raw_len = 0` is stored as `0, 0` with no frame. The frame is an ordinary zstd frame (the writer compresses in one shot, so the content size is recorded; any level decodes). `LEB` is unsigned LEB128, at most 10 bytes.

* **chunk_index**: `n_chunks + 1` fixed-width 24-byte records `{u64 off, u32 len, u32 first_col, u64 nnz_before}`. `off` is relative to the start of the `chunks` section; chunk `c` occupies `[off_c, off_c + len_c)`; chunks are contiguous (`off_{c+1} = off_c + len_c`); `first_col` is strictly increasing from 0; the extra last record is a sentinel `{off = chunks length, len = 0, first_col = n, nnz_before = nnz}`. Chunk `c` holds columns `[first_col_c, first_col_{c+1})` and `nnz_before_{c+1} - nnz_before_c` non-zeros. A writer cuts a chunk after `chunk_cols` columns, before the column that would take it past its non-zero budget (writer defaults below; a single column is always one chunk), or when it would exceed 2^27 non-zeros, whichever comes first, so chunks can have different widths; a reader accepts any chunk with fewer than 2^28 non-zeros. When every chunk except the last has exactly `chunk_cols` columns, chunk `c` of column `j` is `j / chunk_cols` (one multiply); otherwise find it by binary search on `first_col`.
* **tables** (codec 1; empty for codec 2): three consecutive `STREAM`s holding the static entropy tables TC (column counts), TG (gap and value-flag symbols) and TR (value residuals), serialised as in 5.1.
* **rows** (codec 1; empty for codec 2): one `STREAM` whose raw bytes are `LEB(key_0) LEB(key_1) ... LEB(key_{m-1})`, the row key of every canonical row in canonical order (5.1, "Row order"). The decoder derives the stored-to-canonical permutation from it.
* **chunks**: the chunk streams, each laid out as in 5.1 (codec 1) or 5.2 (codec 2). Chunks are independent: decoding chunk `c` needs only its bytes, the tables, and `m`.
* **cols**: the column names part, by `cols_kind`: `Inline` = one `STREAM` of the NUL-terminated names (`n` names, `name\0name\0...`); `PackSubset` = one `STREAM` of `LEB(zigzag(index_i - index_{i-1}))` with `index_{-1} = 0` and `zigzag(d) = (d << 1) ^ (d >> 63)` on 64-bit signed `d`; `Pack`, `Cells`, `None` = empty.
* **kv**: empty when the matrix has no key/value pairs; otherwise `u32 npairs` followed by one `STREAM` of `key\0value\0` pairs in ascending byte order of the key (legacy `user_kv`).
* **extra**: the row names part, same layouts as `cols` with `m` names (`Cells` is invalid). Trailing bytes after the part are reserved and ignored.

**Writer defaults** (measured in `bench/compression/notes/m_w1.md`; a reader never depends on them): `lanes = 32`, `prob_bits = value_prob_bits = 10`, `classes_per_octave = 4`, `ctx_kind` = the smallest by estimate among 0..4 (kind 0 without estimating from 2 million non-zeros), chunks of about 48,000 non-zeros: `chunk_cols` is the power of two in [128, 4096] nearest (geometric midpoint) to 49,152 / (nnz / n), which gives 256 columns for typical dense 10x data and 4096 for sparse matrices; and a chunk ends before the column that would take it past `chunk_nnz_max` = 49,152 non-zeros (EncodeOptions `chunk_nnz_max`: 0 = this default, `UINT32_MAX` / Python -1 = no budget, the fixed-width chunks written before 2026-10-24). The budget matters for matrices whose column density varies: a mean over mostly empty droplets gives 4096-column chunks, and the called cells (dense columns) then shared chunks of several hundred thousand non-zeros. Measured on the compression corpus (7 samples plus 3 of GSE145370, exon + intron; `bench/pz2_chunks/`): 48k costs +0.25 % in member bytes and cuts the chunk bytes fetched for one random called cell from 3.77 MB to 1.00 MB in total (0.27x; 1 % of the cells 0.64x, all called cells 1.004x); single-thread full decode is about 20 % slower (more chunks), a few ms per sample. A 24k budget would give 0.14x for +0.6 %. Side streams (names, rows, tables) use zstd level 19.

### 4.3 Row order and consumer contract

`row_order = 1` stores rows in the file's frequency-class order (rows sorted by (class descending, canonical id ascending), classes
from per-row nnz, `classes_per_octave` per factor of 2; exact definition in 5.1). The decoder then emits ascending stored ids with no sort. A decoder offers:

* `native`: CSC in stored row space plus `row_perm` (stored id -> canonical id); names are permuted once per member.
* `canonical`: CSC with canonical row ids ascending (exactly the legacy matrix); costs a per-column sort.
* `gene`: per-gene aggregated CSC using a per-member stored-id -> gene map (aggregation does not need sorted input).

### 4.4 Names

Row names come from a vocabulary pack (section 6) when the member's row names equal the pack's list byte for byte; otherwise inline.
Column names come from the sample `cells` table or a whitelist pack when they equal it; otherwise inline. Exon and intron matrices of a
sample share one column list (verified: identical barcodes and order); they reference the `cells` table.

### 4.5 Values, limits, fallback

Codec 1 handles any `m < 2^21` and any u32 value (including 0) in value types 1..3, and f32 matrices whose values are all non-negative integers below 2^24 (`flags` bit 0). Codec 2 handles everything else (any `m` up to 2^32 - 1; f32 stored as bit patterns). Empty matrices (`nnz = 0`, `n = 0` or `m = 0`) are legal in both codecs. The writer's `auto` choice: codec 1 when allowed, and additionally codec 2 when the codec-1 member is smaller than 64 KiB, keeping the smaller. The row-id limit is a property of the symbol alphabet (gap classes reach 2^21), not of the container.

### 4.6 Canonical digest

SHA-256 over: `"PZ2CANON1"`, u32 m, u32 n, u64 nnz, u8 value_type, then for each column ascending: u32 count, the canonical row ids
(u32 each, ascending), the values (u32 each, f32 as bit pattern); then u32 row-name count + each name NUL-terminated; same for column names;
then sorted key/values `key\0value\0`. digest16 = first 16 bytes. Identical digests mean identical canonical matrices.

Clarifications fixed by the reference implementation (`canonical_digest`): all integers in the hashed stream are little-endian; `value_type` is the header byte (1..4) and the values of types 1..3 are the numbers widened to u32, of type 4 the IEEE-754 binary32 bit pattern; the names are the *logical* names (names stored as `Pack`, `PackSubset` or `Cells` references are hashed as the names they stand for, which is why the writer needs them even though it does not store them); a matrix with `None` names hashes a name count of 0 and no names; the key/value pairs are hashed in ascending byte order of the key, with no count prefix. A writer that cannot supply the logical names stores the digest as zero (`has_digest` / `compute_digest = false` in the C++ API) and a verifier skips it.

## 5. Codecs and the cells table

### 5.1 Codec 1: lane rANS

Codec 1 codes each chunk as `L` lock-step interleaved static rANS lanes that share one 16-bit word stream. Everything is integer arithmetic on 32-bit unsigned values (wrap-around never occurs for valid streams). The decoder is defined by the reference loop at the end of this section; the scalar, AVX2 and AVX-512 implementations produce identical output. It handles `m <= 2^21 - 1` and every u32 value (including 0).

**Parameters** (header): `L` = `lanes` (16, 32 or 64); `pb` = `prob_bits`, `pbv` = `value_prob_bits` (8..12); `ctx_kind`; `cpo` = `classes_per_octave`. `ctx_kind` selects `(sh, cap, ks, kcap)`: kind 0 = (0, 39, 0, 11), 1 = (0, 39, 1, 5), 2 = (1, 19, 1, 5), 3 = (0, 39, 0, 0), 4 = (1, 19, 0, 0). Define `npc = cap + 1`, `nk = kcap + 1`.

**Row order.** For canonical row `i` with `cnt_i` non-zeros in the whole matrix, `key_i = 0` if `cnt_i = 0`; else, with `lg = floor(log2 cnt_i)`: `key_i = cnt_i` if `cpo = 0`, otherwise `1 + lg*cpo + floor((cnt_i - 2^lg) * cpo / 2^lg)`. Stored row ids are the ranks of the rows sorted by `key` descending, then canonical id ascending; `perm[s]` is the canonical id of stored id `s`. Codec 1 works entirely in stored ids; inside every column they ascend.

**Classes.** A u32 number `x` is split into a class `c` (0..123) and `nb(c)` extra bits `ex`: if `x < 8`: `c = x`, `nb = 0`. Otherwise with `b = floor(log2 x)`: `nb = b - 2`, `ex = x mod 2^nb`, `c = 8 + (b - 3)*4 + ((x >> nb) mod 4)`. Inverse: `e = c >> 2`, `mm = c mod 4`; `nb = max(e - 1, 0)`; `base(c) = (mm | (e > 0 ? 4 : 0)) << nb`; `x = base(c) + ex`. Class tables are padded to 128 entries (a corrupt stream can produce `c` up to 127; decoders must not read outside the table).

**Symbols.** Walk a column's non-zeros in stored-id order with `PP = 0` at the column start. For the element with stored id `r` and value `v`: `g = r - PP`; `flag = (v != 1)`; the gap symbol is `sym = 2*c(g) + flag` with extra bits `ex(g)`; then `PP = r + 1`. If `flag`: residual `q = (v = 0 ? 0 : v - 1)` is split into its class `c2(q)` and extra bits. A column with `k` non-zeros has `kraw = floor(log2(k + 1))`.

**Contexts.**
* With `q = p + 2` and `lq = floor(log2 q)`: `posb(p) = 2*lq + ((q >> (lq - 1)) mod 2) - 2` (two buckets per octave of `p + 2`; `posb(0) = 0`, `posb(1) = 1`).
* Gap context: `ctx = kc*npc + pc` with `kc = min(kraw >> ks, kcap)` and `pc = min(posb(PP) >> sh, cap)`; the table entry index is `(ctx << pb) + slot`.
* Residual context: `rc = min(posb(r) >> 1, 20)*4 + dk`, `dk = min(floor(11*kraw / 32), 3)`, where `r` is the element's stored id; the index is `(rc << pbv) + slot`.

**Tables.** TC: 1 context, alphabet 124 (the class of a column count), 12 probability bits. TG: `npc*nk` contexts, alphabet 248 (`sym`), `pb` bits. TR: 84 contexts, alphabet 124 (`c2`), `pbv` bits. Each is one `STREAM` whose raw bytes are `LEB(nused)` then, for every used context in increasing order, `LEB(ctx - prev_ctx)` (`prev_ctx = 0` before the first), `LEB(nsym)`, and for every symbol with non-zero frequency in increasing order `LEB(sym - prev_sym)` (`prev_sym = 0` before the first) and `LEB(freq)`. For a used context the frequencies are in `[1, 2^pbits - 1]` and sum to exactly `2^pbits`. Expanded decode table of a context (`2^pbits` entries): slots `[cum, cum + freq)` of symbol `sym` hold `(sym, freq, bias = slot - cum)` with `cum` the sum of the frequencies of the smaller symbols. A reader rejects tables that violate these rules. (Informative, for byte-reproducible encoding: counts are scaled with `max(1, floor(count * 2^pbits / total))`, then single units are added to the symbol with the largest `count * (log2(f+1) - log2 f)` or removed from the symbol with the smallest `count * (log2 f - log2(f-1))` until the sum is `2^pbits`; a context with one symbol gives it `2^pbits - 1` and symbol 0 (or 1) frequency 1. The logarithms are a fixed integer table so the result is platform independent.)

**rANS.** The state `X` is a u32 kept in `[2^16, 2^32)`. Decoding a symbol from a table with `P` probability bits: look up `e = table[ctx][X mod 2^P]`; `X = freq*(X >> P) + bias`; if `X < 2^16` then `X = (X << 16) | next_word`. A raw field of `n <= 16` bits: `ex = X mod 2^n`; `X = X >> n`; refill as above. A field of `n` in 17..32 bits is two raw fields, the low 16 bits first and then the high `n - 16` bits (`ex = ex_low | ex_high << 16`). `next_word` is the next unread little-endian u16 of the chunk's word stream. After a valid decode every state equals `2^16` again and every word has been consumed; decoders check this and report corruption otherwise.

**Chunk stream layout.**

```
LEB nwc | LEB nw | u32 cstate | u16 cwords[nwc] | LEB pp0 (one per lane that starts inside a column, see below) | u32 state[L] | u16 words[nw]
```

*Column counts.* Starting from `X = cstate` and reading `cwords`, for each of the chunk's columns in order: decode a TC symbol (the class `c`), then its raw extra bits; `k_j = base(c) + ex`. Afterwards `X` must be `2^16`, all `nwc` words consumed, and `sum k_j` must equal the chunk's non-zero count from the chunk index.

*Lanes.* With `N = sum k_j`, `S = N div L`, `t = N mod L`: lane `l` owns the contiguous element slice starting at `e0(l) = l*S + min(l, t)` of length `cnt(l) = S + (l < t ? 1 : 0)`; a slice may start in the middle of a column. `steps = S + (t > 0)`. Lanes with `cnt(l) = 0` (when `N < L`) are never touched and keep `state[l] = 2^16`; the `L` states are always present, also when `N = 0`. For each lane with `cnt(l) > 0` that starts inside a column (offset `o > 0` into column `j`) the chunk header stores `pp0 = (stored id of the previous element of that column) + 1`, in lane order, as `LEB`. The lane's initial state is column `j` (the column containing element `e0(l)`), `rem = k_j - o`, `PP = o > 0 ? pp0 : 0`; later columns of the lane are the following non-empty columns. The lane's initial rANS state is `state[l]`. Words are read from `words`.

*Reference decode loop* (per chunk; `out_id[e]`, `out_val[e]` are the chunk's `N` stored ids and values; for every lane the context values `kraw`/`dk` come from the full count `k` of the column the lane is in):

```
for s in 0 .. steps-1:                                  # lanes with s >= cnt(l) are skipped in every phase
  A  (l = 0..L-1): e = TG[ctx(l)][X[l] mod 2^pb]; X[l] = e.freq*(X[l] >> pb) + e.bias; refill; sym[l] = e.sym
  B  (l ascending): c = sym[l] >> 1; nb = nbits(c); lo = min(nb,16); ex = X[l] mod 2^lo; X[l] >>= lo; refill
  B2 (l ascending, only if nb > 16): hi = nb - 16; ex |= (X[l] mod 2^hi) << 16; X[l] >>= hi; refill
     rank[l] = PP[l] + base(c) + ex
  C1 (l ascending, only if sym[l] & 1): e2 = TR[rc(l)][X[l] mod 2^pbv]; X[l] = e2.freq*(X[l] >> pbv) + e2.bias; refill
  C2 (same lanes): c2 = e2.sym; nb2 = nbits(c2); lo = min(nb2,16); ex2 = X[l] mod 2^lo; X[l] >>= lo; refill
  C3 (same lanes, only if nb2 > 16): hi = nb2 - 16; ex2 |= (X[l] mod 2^hi) << 16; X[l] >>= hi; refill
  emit (l ascending): q = base(c2) + ex2 if sym[l] & 1;  value = (sym[l] & 1) ? (q = 0 ? 0 : q + 1) : 1
     out_id[e0(l) + s] = rank[l]; out_val[e0(l) + s] = value; PP[l] = rank[l] + 1; rem[l] -= 1
     if rem[l] = 0 and s + 1 < cnt(l): move to the lane's next non-empty column: rem = k, PP = 0, recompute kraw, dk
```

`refill` means: if `X < 2^16` then `X = (X << 16) | next_word` (the shared word stream is consumed in the order the phases above visit lanes). `ctx(l)` uses `kraw` and `PP[l]` as defined under Contexts; `rc(l)` uses `rank[l]`.

The decoder output is the stored-id CSC: `indptr` is the running sum of the `k_j`; `indices` are the stored ids; `data` are the values (for `flags` bit 0 each value `v` stands for the float `v`). Canonical output maps every id through `perm` and sorts each column ascending (ids within a column are unique).

*Encoder (informative).* The encoder runs the same schedule in reverse (steps descending; inside a step phases C3, C2, C1, B2, B, A; lanes descending), pushing symbols with `X = ((X / f) << P) + (X mod f) + cum` after emitting the low 16 bits of `X` whenever `X >= f << (32 - P)` (for a raw field of `n` bits: when `X >= 2^(32-n)`, then `X = (X << n) | ex`), starting every lane at `X = 2^16`; the emitted words, reversed, form the word stream, and the final lane states are `state[l]`. For fields wider than 16 bits the high part is pushed first. The count stream is a single-lane instance of the same scheme.

*Integrity and bounds.* A reader verifies that the declared `nw`/`nwc` words are consumed exactly and all states return to `2^16`, that the chunk's counts sum to the index `nnz`, that the lane stream fits in the chunk, and that decoded ids are `< m` before using them as indices. A chunk blob must be followed by at least 1024 readable bytes (or be decoded from a zero-padded copy), because vector refills load ahead.

### 5.2 Codec 2: generic

For matrices that codec 1 cannot or should not code (`m >= 2^21`, f32 values that are not exactly integral, or a member where codec 2 is smaller, which happens for tiny matrices). Row ids are canonical (`row_order = 0`), so `tables` and `rows` are empty and native and canonical decode are identical. A chunk is three consecutive `STREAM`s (4.2):

```
STREAM counts | STREAM gaps | STREAM values
```

* `counts`: `LEB(k_j)` for every column of the chunk (number of non-zeros).
* `gaps`: for every column, for every non-zero in ascending row order: `LEB(row - prev - 1)` with `prev = -1` at the start of the column (so the first gap is the row id itself and consecutive rows give 0).
* `values`: value types 1..3 and f32 with `flags` bit 0: `LEB(value)` per non-zero (for `flags` bit 0 the value is the integer the float equals). Other f32 matrices: the 4-byte little-endian bit pattern of every value (no LEB).

Each stream is one zstd frame (the reference writer uses level 19; the level is not part of the format). Reader checks: the counts sum to the chunk's non-zeros from the chunk index, every row id is `< m`, no trailing bytes remain in any stream.

### 5.3 Cells table (kind 2)

Columnar, one row per matrix column of the sample in matrix column order:

```
magic "CEL2", u16 version, u16 n_cols, u32 n_rows,
n_cols x { name_len u16, name, dtype u8 (1 u8, 2 u16, 3 u32, 4 i32, 5 f32, 6 f64, 7 bool-bitmap, 8 string(NUL-joined), 9 barcode),
           enc u8 (0 raw, 1 zstd, 2 delta+zstd), off u64, len u64 }
column bodies (64-aligned)
```

Required columns: `barcode` (dtype 9: whitelist indices when the sample has a whitelist pack, else strings), `called` (bitmap),
`n_umi_exon`, `n_umi_intron`, `n_feat_exon`, `n_feat_intron` (u32; computed from the matrices at write time, also enables search).
Optional columns carry any per-cell table of the legacy bundle (cell_calls p-values and method, doublet scores, cell-cycle scores, ambient
contamination, cell QC metrics) so those TSV members can be derived by recipe. The migration also writes `called_v2` (bitmap) and `called_v2_fdr` (f32; NaN =
not tested): the stored call plus the uncalled barcodes EmptyDrops separates from ambient RNA (`singlet.v2.cellcall`, design and
validation in docs/called-v2.md); the cells member's metadata and its manifest entry carry the call's parameters as `called_v2`
(method, version, ambient bound, alpha, pool size, FDR, seed, `validated`). `called` stays the stored call and the default
selection. Content digest = SHA-256 over `"CEL2CANON1"` + for each
column in name order: name, dtype, raw little-endian values.

## 6. Packs

Format: as specified in `bench/compression/notes/w4_vocab.md` (structured gene table + per-chromosome delta-coded coordinates, zstd-19),
wrapped as:

```
magic "SPK2", u16 version, u16 kind (1 row vocabulary, 2 barcode whitelist, 3 composite), u32 header_len, header JSON
{"build": ..., "member": "exon"|"intron"|..., "n": ..., "sha256_names": ...}, body
```

Pack id = digest16 of the whole file; matrices store the first 8 bytes. Packs are immutable; a revised reference produces a new pack.
Python wheels ship human and mouse vocabularies and the 10x whitelists; R and other builds fetch `v2/ref/<id>.pack` on first use and verify
sha256 from `v2/ref/index.json`.

## 11. Reading only some modalities (clients)

Every member has its own byte range, so a client that wants some modalities downloads only those members. The Python, R and MCP
clients share one vocabulary (`MODALITIES` in `python/singlet/v2/client.py`, `.v2_modality_members` in `r/R/v2.R`,
`functions/_shared/v2-load-modalities.ts` in the website):

| name | members fetched | Python (AnnData) | R (SingleCellExperiment) |
|---|---|---|---|
| `counts` | `exon_counts.1pz` + `intron_counts.1pz` | `X` = spliced + unspliced (summed by the client) | assay `counts` |
| `spliced` | `exon_counts.1pz` | `layers["spliced"]` | assay `spliced` |
| `unspliced` | `intron_counts.1pz` | `layers["unspliced"]` | assay `unspliced` |
| `splice_junctions` | `sj_counts.1pz` | `obsm["splice_junctions"]` (cells x junctions CSR) | `altExp("splice_junctions")` |
| `psi` | `sj_counts.1pz` | `obsm["psi"]` (float32, true PSI computed from the junctions) | `altExp("psi")` |
| `mt` | `mt_heteroplasmy.1pz` | `obsm["mt"]` | `altExp("mt")` |
| `vdj` | `vdj_gene_usage.1pz` | `obsm["vdj"]` | `altExp("vdj")` |

* Storage stays exon + intron: there is no summed counts member. `counts` needs both matrices; `spliced` or `unspliced` alone fetch one.
* The `cells` table is always read (barcodes, called flag, the statistics `where=` filters on).
* The default is `counts` + `spliced` + `unspliced` (`counts` alone with `layers=False`), i.e. what clients read before this option.
  Without `counts`, `X` is `None` (R: no `counts` assay); without any gene-level modality the gene axis is empty and the data are in
  `obsm` / `altExp`. Feature names of an `obsm` modality are in `uns["obsm_features"][name]`; `singlet.v2.client.modality_anndata(adata,
  name)` makes it its own AnnData. Samples are combined on the union of their feature names (first-seen order).
* Aliases: `x`, `exon`, `intron`, `junctions`, `sj`, `splice_psi`, `mt_heteroplasmy`, `vdj_gene_usage`.
* Availability comes from the manifest, before any sample byte is read: a modality is present when its member is a pz2 matrix with
  rows and columns (a `stub-v1` recipe, as for `mt_heteroplasmy.1pz` in the pilot, is absent). An explicit request for a modality that
  no requested sample carries stops with an error listing what the samples have; a sample that lacks a requested feature modality
  contributes empty rows (with a warning), and one that has none of the requested matrices is skipped like an empty sample.
* Whole members are coalesced only across alignment padding (gap < 64 bytes), so another member's body is never downloaded along with
  a selection; large samples keep the two-phase plan (cells table + prefixes, then only the chunk runs of the selected members that
  hold the wanted cells), so `where=` / `obs_filter` compose with `modalities`.
* A legacy `.singlet` bundle is a single download: with `modalities` the result is subset after the download, with a warning.
* MCP: `get_partial_download`, `list_bundle_files`, `get_download_url`, `get_modalities` and `slice_cells` take `modalities` and answer
  with the byte ranges of only those members (plus `cells`).

Measured on the pilot (GSE145370 / GSM4317423, a 3,186,387-byte object, 2,722 called cells; bytes on the wire for one sample, manifest
and packs excluded): default 1,077,906; `counts` 1,077,906; `spliced` 723,670; `unspliced` 533,172; `splice_junctions` 2,136,697 (the
junction matrix is the largest member); `vdj` 325,127.

## 12. Shared splice-junction table

Status: DRAFT (2026-10-23), prototype `python/singlet/v2/junctions.py`, benchmark `bench/junctions/bench_table.py`
(results `bench/junctions/results_GSE145370.json`). Not used by the migration yet.

Today every sample stores its junction names inline in `sj_counts.1pz` (`chr7:26402-31059`, ...), which is 38% of the junction bytes of
the pilot (7.2 of 18.8 MB) and gives clients only strings to match junctions across samples. Instead, every junction the atlas uses gets
one integer id per reference build, a sample stores its junction rows as ids, and the table is a first-class atlas resource: the same id
in every sample, study and aggregate.

### 12.1 Ids and coordinates

* A junction is `(chrom, start, end)` in the pipeline's convention: `start` = 0-based position of the first intron base, `end` = 0-based
  position of the first exon base after the intron (the intron is `[start, end)`), so `f"{chrom}:{start}-{end}"` is the pipeline's name
  byte for byte. Strand is an attribute, not part of the key (the pipeline counts junctions unstranded).
* Ids are `u32` below `LOCAL_BASE = 2^31`, assigned per build and **never renumbered**: a table version only appends segments, so an id
  means the same junction in every later version (`build_version(..., previous=)` refuses anything else).
* Ids `LOCAL_BASE + k` inside a sample mean row `k` of that sample's own junction list (12.4). A junction that is local in samples
  written before it entered the table is matched later by coordinates (`JunctionTable.find`), never by rewriting objects.

### 12.2 Objects

Both are SPK2 packs (section 6), stored as `v2/ref/<id>.pack` and listed in `v2/ref/index.json` (`kind` `junction-segment` /
`junction-version`, plus `build`).

* **Segment** (pack kind 4, header `build`, `coder` = `JX1`, `coords`, `id_lo`, `n`, `tier`, `chroms`): ids `[id_lo, id_lo + n)`, rows in
  genomic order (chromosome name in byte order, start, end), so a segment's id order is its genomic order. Body: `u32 n`, then six
  streams, each `u8 width, u32 n, u32 clen` + zstd-19 of the `width` low little-endian byte planes of the values (`width` = bytes of the
  largest value):

  | stream | values |
  |---|---|
  | `chrom_runs` | pairs (chromosome index into `chroms`, row count) |
  | `start_delta` | start minus the previous row's start, modulo 2^32 (across chromosome boundaries too: one wrapping uint32 cumulative sum restores every start) |
  | `length` | end - start |
  | `attr` | u8: bits 0-1 strand (0 unknown, 1 +, 2 -), bits 2-4 motif (STAR codes: 0 non-canonical, 1 GT/AG, 2 CT/AC, 3 GC/AG, 4 CT/GC, 5 AT/AC, 6 GT/AT), bit 5 annotated (an intron of an annotated transcript), bit 6 donor on an annotated intron start, bit 7 acceptor on an annotated intron end |
  | `gene` | zigzag of the uint32 difference of (gene index + 1) into the build's exon-pack gene table; 0 = none |
  | `n_tx` | annotated transcripts using the junction, saturating at 255 |

  Decoding is numpy only (zstd, `frombuffer`, shifts, one `cumsum`); after it, id -> coordinates is an array index (O(1)), coordinates ->
  id is a binary search on (chrom, start) plus a vectorised scan of the few rows sharing that start.
* **Version** (pack kind 5, header `build`, `version`, `n`, `segments` = `[{id, id_lo, n, tier, bytes}]` contiguous from id 0, empty
  body): what samples reference. A client needs the segments that hold the ids it meets; `JunctionTable(version, segments, fetch=)`
  fetches a missing segment by its pack id (sha256-checked, like every pack) the first time an id in its range is looked up.
* **Tiers.** `core` segments ship with the Python and R packages (like the vocabulary packs); `rare` segments are fetched from R2 on
  demand and cached. Transcript-level detail (which transcripts use a junction) would be a separate optional pack (not specified yet),
  not in the core.

### 12.3 Building a table version

Inputs per build: the GTF of the reference (annotated introns = consecutive exons of each transcript; gene, transcript count, strand;
`read_gtf`), the genome FASTA (motif and, for unannotated junctions, strand; `motif_from_genome`), and a **junction census** of the atlas:
for every sample, its junction names and per-junction UMIs and cells in called cells (from the legacy `sj_counts.1pz`, whose names sit
in one range at the end of the member, so the census reads little more than that range plus the matrix once on Clipper).
STAR's `SJ.out.tab`, where a bundle keeps it, cross-checks motif, strand and annotation.

Tier rules (thresholds are parameters of the build and recorded in the version header):

* `core` = every annotated junction of the build, plus unannotated junctions that pass the noise filter (12.6) in at least 3 studies;
* `rare` = other junctions seen in at least 2 samples;
* everything else stays local to its sample.

Version 1 is cut from the census before the campaign migrates any sample. Later versions append segments (new annotated junctions from a
newer annotation of the same build, junctions that became recurrent); they never change an existing id. The exon-pack proxy
(`annotation_from_exon_pack`: junction ends on merged-exon boundaries) sets only the donor/acceptor bits and the gene; it is what the
prototype uses where no GTF is at hand, not a replacement for the GTF.

### 12.4 Junction rows of a sample

* `sj_counts.1pz` keeps its pz2 layout; its row names become `pack_subset` with the version's pack id and `pack_index` = the row ids,
  strictly ascending: table ids first, then `LOCAL_BASE + k`. The matrix rows are in that order.
* The sample's own junctions are the member `sj_counts.1pz.local` (kind 3 or 5): `u16 n_chroms, u32 names_len`, NUL-joined chromosome
  names, then a segment body (12.2) without ids, rows in genomic order. Absent when every junction is in the table.
* The member `sj_counts.1pz.legacy_order` (kind 3 or 5, `encode_perm`: zigzag deltas of `perm`, byte planes, zstd) holds the legacy
  row order: v2 row `r` is legacy row `perm[r]` (12.5).
* The logical matrix of the member is the legacy one: `V2Sample.matrix()` (and the bundle API, `V2Bundle.read`) return the rows in the
  legacy order with the legacy names (`to_legacy`), and the member digest (header and member table) is the canonical digest of that
  legacy matrix. `matrix(..., order="stored")` gives the stored (table) order.
* `splice_psi.1pz` (derived, section 9) is unaffected: its recipe reads `sj_counts.1pz` through the context, which sees the legacy matrix.
* Clients reading data (`modalities=`, section 11) get the table order: `row_names(table, ids, local)` gives the names, and `.local`
  is fetched only when ids at or above `LOCAL_BASE` occur. Integer ids are the natural key for combining samples (no string
  matching); exposing them next to the names (`uns["obsm_ids"]`) is the next client step. The R reader does not resolve
  `pack_subset` junction rows yet.
* Migration: `migrate.Options(junction_table=<JunctionTable>)` writes `sj_counts.1pz` this way (`_junction_rows`, with the table's
  packs reachable through `Options.packs`); stage 2 and `verify` check it against the legacy member exactly like any other matrix, and
  `write_outputs` ships the version and its segments with the study's packs (`index.json` kinds `junction-version`,
  `junction-segment`). The manifest records the version in `packs.junctions` (absent when the junction rows are inline).
* Choosing the table: `python -m singlet.v2.migrate --junction-table auto` (`Options(junction_table="auto")`) takes, per study,
  the newest `junction-version` published for the study's reference build in `v2/ref/index.json` (`junctions.published_table`;
  packs downloaded from the data host and sha256-checked); a build with no published table keeps inline names. A version pack id
  or `.pack` path pins one version; `none` (the CLI default) writes inline names. `scripts/v2_campaign.py run` passes
  `--junction-table auto` unless told otherwise (`--junction-table none`). Version 1 is published for GRCh38-2024-A, GRCm39-2024-A,
  GRCz11, Mmul_10 and mRatBN7.2 (`bench/junctions/v1/`); the GRCh38-GRCm39 barnyard reference has none yet.

### 12.5 Row order (decided 2026-10-23: store the permutation)

The legacy row order is the order in which the pipeline first met each junction while reading the BAM. Every legacy member must still
regenerate byte for byte (section 1, D15 unchanged), so the permutation is stored (`.legacy_order`, 12.4): about 33 KB per sample on
the pilot (458,787 B for 14 samples), roughly 2.3 GB for the atlas. The alternative considered, accepting table order and verifying as
named matrices, was not taken.

### 12.6 Atlas aggregates and isoform use

Per-junction aggregates live next to the cell index (`docs/format-v2-cell-index.md`), as SCX1 objects in `v2/cidx/obj/` referenced from
the index directory (`"junctions": {"table_version": <pack id>, "ct": [keys per organism partition], "tot": key}`), with the same
cell-type / tissue dictionary codes as that index version:

* `jx_ct`: one row per (junction id, cell type, tissue) with any count, columns `jid` u32, `ct` u16, `tissue` u16, `n_cells` u32,
  `n_samples` u32, `n_umi_lo` u32, `n_umi_hi` u32; sorted by `(jid, ct, tissue)` so zone maps on `jid` (genomic order within a segment)
  prune by region.
* `jx_tot`: one row per junction id: `n_studies`, `n_samples`, `n_cells` (u32), `n_umi_lo` / `n_umi_hi` and `n_umi_ambient_lo` /
  `n_umi_ambient_hi` (UMIs in uncalled barcodes of the same samples, the empty-droplet noise model; it survives as this aggregate, or
  from a per-sample ambient profile, if uncalled barcodes are pruned from matrices).
* SCX1 values and zone maps are u32 (cell index 4.1), so atlas-wide UMI sums, which can pass 2^32 for highly expressed junctions over
  ~297 M cells, are split into low and high words. Row groups of 65,536 rows and objects of about 2^21 rows, like the cell shards.

Uses:

* **PSI and exon inclusion per cell type / tissue.** Junction events are the junctions sharing a donor or an acceptor (`recipes_psi`).
  Pooled PSI of junction `j` in group `g` = `n_umi(j, g) / sum over the event of n_umi(k, g)`, with a beta-binomial interval from the
  counts; exon inclusion for a cassette exon = inclusion junctions against the skipping junction. Pooling over hundreds of millions of
  cells gives the counts per group that single cells (mostly 0 or 1 read per junction) cannot.
* **Novel junction discovery with noise control.** An unannotated junction is reported when it is recurrent (`n_studies` >= 3, from
  independent studies so one library's artefact cannot pass), has read support (`n_umi` and `n_cells` above build thresholds), a canonical
  motif (GT/AG, GC/AG, AT/AC on either strand), is not explained by ambient RNA (`n_umi_ambient / n_umi` below the study's ambient
  fraction, a binomial test against it), and, where the pipeline records it, a minimum overhang. Each criterion is a column, so the
  thresholds stay a query choice, not baked into the table.
* Building (agreed with the cell-index session, not built yet): the builder lives in `junctions.py`; it encodes the objects with
  `atlas.encode_shard`, names them `obj_key(blob, "scx")` (`v2/cidx/obj/<d16>.scx`, already served by the data Worker) and attaches them
  with `BuildResult.add_extension("junctions", {...}, objects)`, which re-derives the index version id from the new directory content.
  Cell-type / tissue codes come from that build's `directory["dicts"]`; the per-cell codes are read from the shards (or a builder hook
  handing over each sample's `(cols, ct codes)`), and the junction counts from each sample's junction member, called columns only.

### 12.7 Measurements (pilot GSE145370, 14 samples)

Read-only on the 14 pilot samples (`bench/junctions/results_GSE145370.json`). Tiers for one study: core = both ends on annotated exon
boundaries (exon-pack proxy) or seen in >= 3 samples; rare = seen in exactly 2 samples; local = one sample only.

|---|---|
| distinct junctions in the study | 400,127 (core 182,290, rare 23,220, local 194,617) |

| core streams | start_delta 290,970, length 327,449, gene 111,998, attr 31,857, chrom_runs 147, n_tx 34 B |

Speed (wall time, median). The laptop was fully loaded by other jobs during the run: a reference `cumsum` of 1 M uint32 took

| operation | measured (loaded) |
|---|---|
| decode the whole core segment (182,290 junctions) | 39 ms |
| decode a 1.09 M-junction core (scaling test) | 170 ms |

### 14.1 ATAC

| member | kind | content |
|---|---|---|
| `atac_fragments.tsv.gz` | 3 (stored, as written) | bgzip fragments, Cell Ranger layout (`chrom start end barcode read_pairs`), barcodes in the sample's column space; with `atac_fragments.tsv.gz.tbi` (kind 3) so clients can range-read a region |
| `atac_peaks.bed` | 3 (stored, zstd) | the sample's insertion peaks (`atac_peak_caller.h`), narrowPeak-like columns |
| `atac_peak_counts.1pz` | 1 (pz2) | cut sites per peak x the sample's columns; rows `Inline` (`chr:start-end`, the order of `atac_peaks.bed`) |
| `atac_gene_activity.1pz` | 1 (pz2) | fragments over gene body + 2 kb upstream, protein-coding genes x columns; rows `Inline` (`gene_id_gene_name`) |
| `atac_summary.json` | 3 (stored, zstd) | `singlet-atac-summary/1`: barcode layout and whitelist, fragment counts, cell-call method, sample QC with thresholds and pass/fail |

Per-barcode ATAC QC (`fragments`, `tss_enrichment`, `nucleosome_signal`, `frip`, `mito_fragments`, `duplicate_read_pairs`)
are per-cell QC counts: tier-2 columns of the cells table (`docs/CELL-ARCHITECTURE.md`), from `atac_barcode_metrics.tsv`.

* **Multiome.** ATAC barcodes are translated to GEX barcodes (ARC pairs list), so the ATAC members attach to the **GEX
  sample** like ADT does, with columns = the GEX cells table. ATAC barcodes without a GEX column (no GEX reads) are dropped
  from the matrices and counted in `atac_summary.json`; fragments keep them. The joint ARC-style cell call
  (`mixture-gex-atac`) is a cells-table column `called_multiome`; `called` stays the GEX call.
* **scATAC alone.** The ATAC library is its own sample. Its cells table comes from `atac_barcode_metrics.tsv` (columns =
  barcodes with >= 100 fragments or called); `called` is the ATAC call. It has no `exon_counts` / `intron_counts`; readers
  use `atac_gene_activity` where a gene matrix is needed and say so.
* Libraries processed as RNA before this change (139 in `docs/library-type-screen.md`) are re-run with the ATAC path; their
  RNA-mode objects are not migrated.

`modalities=` (section 11): `atac` -> `atac_peak_counts.1pz` (`obsm["atac"]`, names in `uns["obsm_features"]["atac"]`;
R `altExp("atac")`), `gene_activity` -> `atac_gene_activity.1pz` (`obsm["gene_activity"]`), `fragments` -> the fragment
file and its index (not loaded into memory; the client returns a path / byte-range reader). Aliases: `peaks`, `chromatin` ->
`atac`.

### 14.2 Spatial (Visium)

| member | kind | content |
|---|---|---|
| `spatial_positions.tsv` | 3 (stored, zstd) | one row per column of the cells table, in column order: `barcode, spot, array_row, array_col, in_tissue, tissue_prob, primary, umis` (+ `in_tissue_spaceranger, pxl_row_in_fullres, pxl_col_in_fullres` when the authors deposited Space Ranger positions) |
| `spatial_summary.json` | 3 (stored, zstd) | `singlet-spatial-summary/1`: slide list, tissue method, mixture fit, agreement with Space Ranger when available, QC thresholds and pass/fail |
| `spatial_image_lowres.png`, `spatial_scalefactors.json` | 3 (stored, as written) | optional, only when deposited by the authors (GEO supplementary); never generated |

* Spot coordinates are a property of the slide, not a measurement: the slide spot list (`visium-v1_coordinates.tsv`, 4,992
  spots) maps each barcode to `(array_row, array_col)`. Pixel coordinates exist only when the authors deposited them.
* The called set of a Visium sample is its tissue spots (`in_tissue` & `primary`); `cell_calls.tsv` is rewritten with
  `call_method = visium_tissue` and the migration takes `called` from it as for any sample. A spot is not a cell: the
  sample-level `assay` is `Spatial` and cell counts of Visium samples are reported as spots.
* Tier 1 gets sample-level spatial facts only (slide version, tissue spots, median UMIs per tissue spot, QC verdict).

`modalities=`: `spatial` -> `spatial_positions.tsv`; Python `obsm["spatial"]` = `(array_col, array_row)` (scanpy /
squidpy convention: x, y), `obs["in_tissue"]`, `obs["array_row"]`, `obs["array_col"]`, `uns["spatial"]` with the summary
(and the image when present); R `colData` columns and `spatialCoords` for SpatialExperiment.
