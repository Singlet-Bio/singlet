# Singlet v2 data format (`.s2` sample objects, `pz2` matrices, packs, manifests)

Status: DRAFT 1 (2026-10-22), owned by the v2 migration (`bench/compression/PROPOSAL.md`, `docs/v2-migration.md`). Sections 4.1, 4.2, 4.5, 5.1
and 5.2 (written by the codec agent, W1) describe exactly what `include/singlet/pz2/` does and were checked against it; the C++ code is
the reference implementation (header 4.1 is 256 bytes: the original field list summed to 180, not 160, and the codec parameters needed room).
All integers are little-endian. "digest16" = first 16 bytes of SHA-256. Text is UTF-8.

## 1. Goals and invariants

1. **Bit-equivalence.** Every member of a legacy `.singlet` bundle is reproduced exactly from v2: matrices as identical canonical CSC
   triples (indptr, indices, data, row names, column names, key/values), every other member as identical bytes. Each component is
   either regenerated by a pinned recipe or stored ("verify-or-store"): the migration tries the recipe, compares bytes, and stores the
   original when they differ. A v2 file therefore never depends on a recipe that was not verified on that very sample.
2. **Nothing derivable is stored** when the recipe verifies: row names (packs), barcodes (whitelists), permutations, column pointers,
   column sums, filtered matrices, PSI, ambient profiles, QC tables computable from counts.
3. **Random access to cells.** Matrices are column (cell) chunked with a fixed-width chunk index at a known offset; any column range is
   decodable from its chunks alone. One HTTP range request per contiguous run of chunks.
4. **Immutable, content-addressed objects.** A sample object's key contains its digest; rewriting creates a new key. Only study manifests
   are mutable. Cached offsets can never point into a different file.
5. **Fast, portable decode.** Integer-only, byte-identical results on scalar, AVX2, AVX-512 (and future NEON) paths; runtime dispatch.

## 3. Sample object `.s2`

```
offset 0   FileHeader (64 bytes)
           magic        8   "SINGLET2"
           version      u16 = 1
           flags        u16 = 0
           n_members    u32
           table_off    u64  (= 64)
           table_len    u64
           file_len     u64
           sample_id    16   ASCII GSM id, NUL padded
           reserved     8    zero
offset 64  MemberTable  (table_len bytes): n_members entries, each
           name_len u16, name (UTF-8, the legacy member file name, e.g. "exon_counts.1pz", or a v2 name such as "cells")
           kind u8       1 = pz2 matrix, 2 = cells table, 3 = stored blob (zstd), 4 = derived (recipe), 5 = raw (stored as is)
           flags u8      bit0: legacy member (regenerates a member of the legacy bundle); bit1: required for to_anndata
           off u64, len u64      byte range of the member body inside this object (0, 0 for kind 4)
           out_len u64           byte length of the regenerated legacy member (kind 3/4/5) or 0
           crc32 u32             CRC-32 (ISO 3309) of the regenerated legacy bytes for kinds 3/4/5 (equals the legacy ZIP CRC); 0 for 1/2
           digest 16             digest16 of the canonical content (section 4.6 for matrices, section 5 for tables, regenerated bytes otherwise)
           meta_len u32, meta    JSON object: recipe id and parameters (kind 4), zstd level (kind 3), legacy codec facts, etc.
           Member bodies follow, each starting at a multiple of 64.
```

A client normally learns member offsets from the study manifest and fetches exactly one range per member or chunk run; the header
and table make the object self-describing offline.

## 4. Matrix member `pz2` (kind 1)

### 4.1 Header (fixed 256 bytes)

All offsets are byte offsets from the start of the member; integers are little-endian.

| offset | size | field | notes |
|---|---|---|---|
| 0 | 4 | magic | `"PZ2M"` |
| 4 | 2 | version | 1 |
| 6 | 2 | codec | 1 = lane rANS (fast, section 5.1), 2 = generic gaps + zstd (any size, section 5.2) |
| 8 | 4 | m | rows (features) |
| 12 | 4 | n | columns (barcodes) |
| 16 | 8 | nnz | stored non-zeros (explicit zero values count) |
| 24 | 1 | value_type | 1 = u8, 2 = u16, 3 = u32, 4 = f32. For 1..3 this is the legacy `.1pz` `vt_code` (a legacy file may store u32 although all values are small; the migration keeps the legacy code). f32 values are stored as u32 bit patterns (see `flags`) |
| 25 | 1 | row_order | 0 = canonical row ids (codec 2); 1 = class order (codec 1, section 4.3) |
| 26 | 1 | classes_per_octave | 0..8; 0 = exact frequency rank. Meaningful for codec 1 only |
| 27 | 1 | flags | bit 0: value_type 4 coded as integers (every value is a non-negative integer below 2^24 whose float bit pattern round-trips; `-0.0` and NaN never qualify); other bits zero |
| 28 | 4 | chunk_cols | nominal maximum columns per chunk (a chunk may be narrower; see 4.2) |
| 32 | 4 | n_chunks | |
| 36 | 1 | lanes | codec 1: 16, 32 or 64 (written as given for codec 2 and ignored) |
| 37 | 1 | prob_bits | codec 1: precision of the gap/flag tables, 8..12 |
| 38 | 1 | value_prob_bits | codec 1: precision of the residual tables, 8..12 |
| 39 | 1 | ctx_kind | codec 1: context configuration 0..4 (section 5.1) |
| 40 | 8 | row_names_id | pack id prefix (first 8 bytes of the pack digest16) when `rows_kind` is 1 or 2; otherwise zero |
| 48 | 8 | col_names_id | pack id prefix when `cols_kind` is 1 or 2; the ASCII bytes `"CELLS\0\0\0"` when `cols_kind` is 3; otherwise zero |
| 56 | 16 | digest | digest16 of the canonical CSC (section 4.6), or zero when the writer did not compute it |
| 72 | 112 | section table | 7 x {u64 off, u64 len}, in the order rows, cols, kv, tables, chunk_index, chunks, extra; offsets relative to the member start |
| 184 | 8 | total_len | byte length of the whole member |
| 192 | 1 | rows_kind | names kind of the rows (below); 3 is invalid for rows |
| 193 | 1 | cols_kind | names kind of the columns |
| 194 | 58 | reserved | zero |
| 252 | 4 | header_crc32 | CRC-32 (ISO 3309, as zlib) of bytes 0..251 |

Names kinds: 0 `Inline` (names stored in the member), 1 `Pack` (names equal the pack's list, in pack order; nothing stored), 2 `PackSubset` (name `i` is entry `index[i]` of the pack; the index list is stored), 3 `Cells` (columns only: the names are the barcode column of the sample `cells` table; nothing stored), 4 `None` (the matrix has no names; the canonical digest then hashes zero names).

A reader must reject a header whose magic, version, CRC, codec or names kinds are invalid, whose sections do not lie inside `[256, total_len)`, whose `chunk_index` length is not `(n_chunks + 1) * 24`, or that declares codec 1 with `m >= 2^21`.

### 4.2 Sections

Physical order (sections are packed back to back, no padding, no alignment; a section of length 0 has `off` equal to the position it would have had):

```
header (256) | chunk_index | tables | rows | chunks | cols | kv | extra
```

`header + chunk_index + tables + rows` is the **prefix** (`prefix_len = rows.off + rows.len`). It is everything needed to plan and decode any column range; a remote client fetches the first 64 KB (or the prefix length from the header, whichever is larger) and then one range per run of chunks. `cols`, `kv` and `extra` are needed only for names and key/values.

`STREAM` below means `u32 raw_len, u32 zstd_len, zstd frame`; `raw_len = 0` is stored as `0, 0` with no frame. The frame is an ordinary zstd frame (the writer compresses in one shot, so the content size is recorded; any level decodes). `LEB` is unsigned LEB128, at most 10 bytes.

* **chunk_index**: `n_chunks + 1` fixed-width 24-byte records `{u64 off, u32 len, u32 first_col, u64 nnz_before}`. `off` is relative to the start of the `chunks` section; chunk `c` occupies `[off_c, off_c + len_c)`; chunks are contiguous (`off_{c+1} = off_c + len_c`); `first_col` is strictly increasing from 0; the extra last record is a sentinel `{off = chunks length, len = 0, first_col = n, nnz_before = nnz}`. Chunk `c` holds columns `[first_col_c, first_col_{c+1})` and `nnz_before_{c+1} - nnz_before_c` non-zeros. A writer cuts a chunk after `chunk_cols` columns or when it would exceed 2^27 non-zeros, whichever comes first; a reader accepts any chunk with fewer than 2^28 non-zeros. When every chunk except the last has exactly `chunk_cols` columns, chunk `c` of column `j` is `j / chunk_cols` (one multiply); otherwise find it by binary search on `first_col`.
* **tables** (codec 1; empty for codec 2): three consecutive `STREAM`s holding the static entropy tables TC (column counts), TG (gap and value-flag symbols) and TR (value residuals), serialised as in 5.1.
* **rows** (codec 1; empty for codec 2): one `STREAM` whose raw bytes are `LEB(key_0) LEB(key_1) ... LEB(key_{m-1})`, the row key of every canonical row in canonical order (5.1, "Row order"). The decoder derives the stored-to-canonical permutation from it.
* **chunks**: the chunk streams, each laid out as in 5.1 (codec 1) or 5.2 (codec 2). Chunks are independent: decoding chunk `c` needs only its bytes, the tables, and `m`.
* **cols**: the column names part, by `cols_kind`: `Inline` = one `STREAM` of the NUL-terminated names (`n` names, `name\0name\0...`); `PackSubset` = one `STREAM` of `LEB(zigzag(index_i - index_{i-1}))` with `index_{-1} = 0` and `zigzag(d) = (d << 1) ^ (d >> 63)` on 64-bit signed `d`; `Pack`, `Cells`, `None` = empty.
* **kv**: empty when the matrix has no key/value pairs; otherwise `u32 npairs` followed by one `STREAM` of `key\0value\0` pairs in ascending byte order of the key (legacy `user_kv`).
* **extra**: the row names part, same layouts as `cols` with `m` names (`Cells` is invalid). Trailing bytes after the part are reserved and ignored.

**Writer defaults** (measured in `bench/compression/notes/m_w1.md`; a reader never depends on them): `lanes = 32`, `prob_bits = value_prob_bits = 10`, `classes_per_octave = 4`, `ctx_kind` = the smallest by estimate among 0..4 (kind 0 without estimating from 2 million non-zeros), chunks of about 48,000 non-zeros: `chunk_cols` is the power of two in [128, 4096] nearest (geometric midpoint) to 49,152 / (nnz / n), which gives 256 columns for typical dense 10x data and 4096 for sparse matrices. Side streams (names, rows, tables) use zstd level 19.

### 4.3 Row order and consumer contract

`row_order = 1` stores rows in the file's frequency-class order (rows sorted by (class descending, canonical id ascending), classes
from per-row nnz, `classes_per_octave` per factor of 2; exact definition in 5.1). The decoder then emits ascending stored ids with no sort. A decoder offers:

* `native`: CSC in stored row space plus `row_perm` (stored id -> canonical id); names are permuted once per member.
* `canonical`: CSC with canonical row ids ascending (exactly the legacy matrix); costs a per-column sort.
* `gene`: per-gene aggregated CSC using a per-member stored-id -> gene map (aggregation does not need sorted input).

### 4.4 Names

Row names come from a vocabulary pack (section 6) when the member's row names equal the pack's list byte for byte; otherwise inline.
Column names come from the sample `cells` table or a whitelist pack when they equal it; otherwise inline. Exon and intron matrices of a
sample share one column list (verified: identical barcodes and order); they reference the `cells` table.

### 4.5 Values, limits, fallback

Codec 1 handles any `m < 2^21` and any u32 value (including 0) in value types 1..3, and f32 matrices whose values are all non-negative integers below 2^24 (`flags` bit 0). Codec 2 handles everything else (any `m` up to 2^32 - 1; f32 stored as bit patterns). Empty matrices (`nnz = 0`, `n = 0` or `m = 0`) are legal in both codecs. The writer's `auto` choice: codec 1 when allowed, and additionally codec 2 when the codec-1 member is smaller than 64 KiB, keeping the smaller. The row-id limit is a property of the symbol alphabet (gap classes reach 2^21), not of the container.

### 4.6 Canonical digest

SHA-256 over: `"PZ2CANON1"`, u32 m, u32 n, u64 nnz, u8 value_type, then for each column ascending: u32 count, the canonical row ids
(u32 each, ascending), the values (u32 each, f32 as bit pattern); then u32 row-name count + each name NUL-terminated; same for column names;
then sorted key/values `key\0value\0`. digest16 = first 16 bytes. Identical digests mean identical canonical matrices.

Clarifications fixed by the reference implementation (`canonical_digest`): all integers in the hashed stream are little-endian; `value_type` is the header byte (1..4) and the values of types 1..3 are the numbers widened to u32, of type 4 the IEEE-754 binary32 bit pattern; the names are the *logical* names (names stored as `Pack`, `PackSubset` or `Cells` references are hashed as the names they stand for, which is why the writer needs them even though it does not store them); a matrix with `None` names hashes a name count of 0 and no names; the key/value pairs are hashed in ascending byte order of the key, with no count prefix. A writer that cannot supply the logical names stores the digest as zero (`has_digest` / `compute_digest = false` in the C++ API) and a verifier skips it.

## 5. Codecs and the cells table

### 5.1 Codec 1: lane rANS

Codec 1 codes each chunk as `L` lock-step interleaved static rANS lanes that share one 16-bit word stream. Everything is integer arithmetic on 32-bit unsigned values (wrap-around never occurs for valid streams). The decoder is defined by the reference loop at the end of this section; the scalar, AVX2 and AVX-512 implementations produce identical output. It handles `m <= 2^21 - 1` and every u32 value (including 0).

**Parameters** (header): `L` = `lanes` (16, 32 or 64); `pb` = `prob_bits`, `pbv` = `value_prob_bits` (8..12); `ctx_kind`; `cpo` = `classes_per_octave`. `ctx_kind` selects `(sh, cap, ks, kcap)`: kind 0 = (0, 39, 0, 11), 1 = (0, 39, 1, 5), 2 = (1, 19, 1, 5), 3 = (0, 39, 0, 0), 4 = (1, 19, 0, 0). Define `npc = cap + 1`, `nk = kcap + 1`.

**Row order.** For canonical row `i` with `cnt_i` non-zeros in the whole matrix, `key_i = 0` if `cnt_i = 0`; else, with `lg = floor(log2 cnt_i)`: `key_i = cnt_i` if `cpo = 0`, otherwise `1 + lg*cpo + floor((cnt_i - 2^lg) * cpo / 2^lg)`. Stored row ids are the ranks of the rows sorted by `key` descending, then canonical id ascending; `perm[s]` is the canonical id of stored id `s`. Codec 1 works entirely in stored ids; inside every column they ascend.

**Classes.** A u32 number `x` is split into a class `c` (0..123) and `nb(c)` extra bits `ex`: if `x < 8`: `c = x`, `nb = 0`. Otherwise with `b = floor(log2 x)`: `nb = b - 2`, `ex = x mod 2^nb`, `c = 8 + (b - 3)*4 + ((x >> nb) mod 4)`. Inverse: `e = c >> 2`, `mm = c mod 4`; `nb = max(e - 1, 0)`; `base(c) = (mm | (e > 0 ? 4 : 0)) << nb`; `x = base(c) + ex`. Class tables are padded to 128 entries (a corrupt stream can produce `c` up to 127; decoders must not read outside the table).

**Symbols.** Walk a column's non-zeros in stored-id order with `PP = 0` at the column start. For the element with stored id `r` and value `v`: `g = r - PP`; `flag = (v != 1)`; the gap symbol is `sym = 2*c(g) + flag` with extra bits `ex(g)`; then `PP = r + 1`. If `flag`: residual `q = (v = 0 ? 0 : v - 1)` is split into its class `c2(q)` and extra bits. A column with `k` non-zeros has `kraw = floor(log2(k + 1))`.

**Contexts.**
* With `q = p + 2` and `lq = floor(log2 q)`: `posb(p) = 2*lq + ((q >> (lq - 1)) mod 2) - 2` (two buckets per octave of `p + 2`; `posb(0) = 0`, `posb(1) = 1`).
* Gap context: `ctx = kc*npc + pc` with `kc = min(kraw >> ks, kcap)` and `pc = min(posb(PP) >> sh, cap)`; the table entry index is `(ctx << pb) + slot`.
* Residual context: `rc = min(posb(r) >> 1, 20)*4 + dk`, `dk = min(floor(11*kraw / 32), 3)`, where `r` is the element's stored id; the index is `(rc << pbv) + slot`.

**Tables.** TC: 1 context, alphabet 124 (the class of a column count), 12 probability bits. TG: `npc*nk` contexts, alphabet 248 (`sym`), `pb` bits. TR: 84 contexts, alphabet 124 (`c2`), `pbv` bits. Each is one `STREAM` whose raw bytes are `LEB(nused)` then, for every used context in increasing order, `LEB(ctx - prev_ctx)` (`prev_ctx = 0` before the first), `LEB(nsym)`, and for every symbol with non-zero frequency in increasing order `LEB(sym - prev_sym)` (`prev_sym = 0` before the first) and `LEB(freq)`. For a used context the frequencies are in `[1, 2^pbits - 1]` and sum to exactly `2^pbits`. Expanded decode table of a context (`2^pbits` entries): slots `[cum, cum + freq)` of symbol `sym` hold `(sym, freq, bias = slot - cum)` with `cum` the sum of the frequencies of the smaller symbols. A reader rejects tables that violate these rules. (Informative, for byte-reproducible encoding: counts are scaled with `max(1, floor(count * 2^pbits / total))`, then single units are added to the symbol with the largest `count * (log2(f+1) - log2 f)` or removed from the symbol with the smallest `count * (log2 f - log2(f-1))` until the sum is `2^pbits`; a context with one symbol gives it `2^pbits - 1` and symbol 0 (or 1) frequency 1. The logarithms are a fixed integer table so the result is platform independent.)

**rANS.** The state `X` is a u32 kept in `[2^16, 2^32)`. Decoding a symbol from a table with `P` probability bits: look up `e = table[ctx][X mod 2^P]`; `X = freq*(X >> P) + bias`; if `X < 2^16` then `X = (X << 16) | next_word`. A raw field of `n <= 16` bits: `ex = X mod 2^n`; `X = X >> n`; refill as above. A field of `n` in 17..32 bits is two raw fields, the low 16 bits first and then the high `n - 16` bits (`ex = ex_low | ex_high << 16`). `next_word` is the next unread little-endian u16 of the chunk's word stream. After a valid decode every state equals `2^16` again and every word has been consumed; decoders check this and report corruption otherwise.

**Chunk stream layout.**

```
LEB nwc | LEB nw | u32 cstate | u16 cwords[nwc] | LEB pp0 (one per lane that starts inside a column, see below) | u32 state[L] | u16 words[nw]
```

*Column counts.* Starting from `X = cstate` and reading `cwords`, for each of the chunk's columns in order: decode a TC symbol (the class `c`), then its raw extra bits; `k_j = base(c) + ex`. Afterwards `X` must be `2^16`, all `nwc` words consumed, and `sum k_j` must equal the chunk's non-zero count from the chunk index.

*Lanes.* With `N = sum k_j`, `S = N div L`, `t = N mod L`: lane `l` owns the contiguous element slice starting at `e0(l) = l*S + min(l, t)` of length `cnt(l) = S + (l < t ? 1 : 0)`; a slice may start in the middle of a column. `steps = S + (t > 0)`. Lanes with `cnt(l) = 0` (when `N < L`) are never touched and keep `state[l] = 2^16`; the `L` states are always present, also when `N = 0`. For each lane with `cnt(l) > 0` that starts inside a column (offset `o > 0` into column `j`) the chunk header stores `pp0 = (stored id of the previous element of that column) + 1`, in lane order, as `LEB`. The lane's initial state is column `j` (the column containing element `e0(l)`), `rem = k_j - o`, `PP = o > 0 ? pp0 : 0`; later columns of the lane are the following non-empty columns. The lane's initial rANS state is `state[l]`. Words are read from `words`.

*Reference decode loop* (per chunk; `out_id[e]`, `out_val[e]` are the chunk's `N` stored ids and values; for every lane the context values `kraw`/`dk` come from the full count `k` of the column the lane is in):

```
for s in 0 .. steps-1:                                  # lanes with s >= cnt(l) are skipped in every phase
  A  (l = 0..L-1): e = TG[ctx(l)][X[l] mod 2^pb]; X[l] = e.freq*(X[l] >> pb) + e.bias; refill; sym[l] = e.sym
  B  (l ascending): c = sym[l] >> 1; nb = nbits(c); lo = min(nb,16); ex = X[l] mod 2^lo; X[l] >>= lo; refill
  B2 (l ascending, only if nb > 16): hi = nb - 16; ex |= (X[l] mod 2^hi) << 16; X[l] >>= hi; refill
     rank[l] = PP[l] + base(c) + ex
  C1 (l ascending, only if sym[l] & 1): e2 = TR[rc(l)][X[l] mod 2^pbv]; X[l] = e2.freq*(X[l] >> pbv) + e2.bias; refill
  C2 (same lanes): c2 = e2.sym; nb2 = nbits(c2); lo = min(nb2,16); ex2 = X[l] mod 2^lo; X[l] >>= lo; refill
  C3 (same lanes, only if nb2 > 16): hi = nb2 - 16; ex2 |= (X[l] mod 2^hi) << 16; X[l] >>= hi; refill
  emit (l ascending): q = base(c2) + ex2 if sym[l] & 1;  value = (sym[l] & 1) ? (q = 0 ? 0 : q + 1) : 1
     out_id[e0(l) + s] = rank[l]; out_val[e0(l) + s] = value; PP[l] = rank[l] + 1; rem[l] -= 1
     if rem[l] = 0 and s + 1 < cnt(l): move to the lane's next non-empty column: rem = k, PP = 0, recompute kraw, dk
```

`refill` means: if `X < 2^16` then `X = (X << 16) | next_word` (the shared word stream is consumed in the order the phases above visit lanes). `ctx(l)` uses `kraw` and `PP[l]` as defined under Contexts; `rc(l)` uses `rank[l]`.

The decoder output is the stored-id CSC: `indptr` is the running sum of the `k_j`; `indices` are the stored ids; `data` are the values (for `flags` bit 0 each value `v` stands for the float `v`). Canonical output maps every id through `perm` and sorts each column ascending (ids within a column are unique).

*Encoder (informative).* The encoder runs the same schedule in reverse (steps descending; inside a step phases C3, C2, C1, B2, B, A; lanes descending), pushing symbols with `X = ((X / f) << P) + (X mod f) + cum` after emitting the low 16 bits of `X` whenever `X >= f << (32 - P)` (for a raw field of `n` bits: when `X >= 2^(32-n)`, then `X = (X << n) | ex`), starting every lane at `X = 2^16`; the emitted words, reversed, form the word stream, and the final lane states are `state[l]`. For fields wider than 16 bits the high part is pushed first. The count stream is a single-lane instance of the same scheme.

*Integrity and bounds.* A reader verifies that the declared `nw`/`nwc` words are consumed exactly and all states return to `2^16`, that the chunk's counts sum to the index `nnz`, that the lane stream fits in the chunk, and that decoded ids are `< m` before using them as indices. A chunk blob must be followed by at least 1024 readable bytes (or be decoded from a zero-padded copy), because vector refills load ahead.

### 5.2 Codec 2: generic

For matrices that codec 1 cannot or should not code (`m >= 2^21`, f32 values that are not exactly integral, or a member where codec 2 is smaller, which happens for tiny matrices). Row ids are canonical (`row_order = 0`), so `tables` and `rows` are empty and native and canonical decode are identical. A chunk is three consecutive `STREAM`s (4.2):

```
STREAM counts | STREAM gaps | STREAM values
```

* `counts`: `LEB(k_j)` for every column of the chunk (number of non-zeros).
* `gaps`: for every column, for every non-zero in ascending row order: `LEB(row - prev - 1)` with `prev = -1` at the start of the column (so the first gap is the row id itself and consecutive rows give 0).
* `values`: value types 1..3 and f32 with `flags` bit 0: `LEB(value)` per non-zero (for `flags` bit 0 the value is the integer the float equals). Other f32 matrices: the 4-byte little-endian bit pattern of every value (no LEB).

Each stream is one zstd frame (the reference writer uses level 19; the level is not part of the format). Reader checks: the counts sum to the chunk's non-zeros from the chunk index, every row id is `< m`, no trailing bytes remain in any stream.

### 5.3 Cells table (kind 2)

Columnar, one row per matrix column of the sample in matrix column order:

```
magic "CEL2", u16 version, u16 n_cols, u32 n_rows,
n_cols x { name_len u16, name, dtype u8 (1 u8, 2 u16, 3 u32, 4 i32, 5 f32, 6 f64, 7 bool-bitmap, 8 string(NUL-joined), 9 barcode),
           enc u8 (0 raw, 1 zstd, 2 delta+zstd), off u64, len u64 }
column bodies (64-aligned)
```

Required columns: `barcode` (dtype 9: whitelist indices when the sample has a whitelist pack, else strings), `called` (bitmap),
`n_umi_exon`, `n_umi_intron`, `n_feat_exon`, `n_feat_intron` (u32; computed from the matrices at write time, also enables search).
Optional columns carry any per-cell table of the legacy bundle (cell_calls p-values and method, doublet scores, cell-cycle scores, ambient
contamination, cell QC metrics) so those TSV members can be derived by recipe. The migration also writes `called_v2` (bitmap) and `called_v2_fdr` (f32; NaN =
not tested): the stored call plus the uncalled barcodes EmptyDrops separates from ambient RNA (`singlet.v2.cellcall`, design and
validation in docs/called-v2.md); the cells member's metadata and its manifest entry carry the call's parameters as `called_v2`
(method, version, ambient bound, alpha, pool size, FDR, seed, `validated`). `called` stays the stored call and the default
selection. Content digest = SHA-256 over `"CEL2CANON1"` + for each
column in name order: name, dtype, raw little-endian values.

## 6. Packs

Format: as specified in `bench/compression/notes/w4_vocab.md` (structured gene table + per-chromosome delta-coded coordinates, zstd-19),
wrapped as:

```
magic "SPK2", u16 version, u16 kind (1 row vocabulary, 2 barcode whitelist, 3 composite), u32 header_len, header JSON
{"build": ..., "member": "exon"|"intron"|..., "n": ..., "sha256_names": ...}, body
```

Pack id = digest16 of the whole file; matrices store the first 8 bytes. Packs are immutable; a revised reference produces a new pack.
Python wheels ship human and mouse vocabularies and the 10x whitelists; R and other builds fetch `v2/ref/<id>.pack` on first use and verify
sha256 from `v2/ref/index.json`.

## 7. Study manifest `v2/m/<GSE>.json`

```json
{
  "format": "singlet-v2", "manifest_version": 1, "gse": "GSE145370", "rev": "<16 hex>",
  "created_at": "...", "reference_build": "GRCh38-2024-A", "pipeline": {...},
  "packs": {"exon": "<packid>", "intron": "<packid>", "whitelist": "<packid or null>"},
  "study_files": {"study_meta.json": {...inline JSON...}, "manifest.json": {"legacy": true, "derived": "recipe ..."}},
  "samples": [
    {"gsm": "GSM...", "key": "v2/s/GSM.../<d>.s2", "bytes": 123, "sha256": "...", "n_columns": 25067, "n_called": 3820,
     "members": {"exon_counts.1pz": {"kind": 1, "off": 4096, "len": 456789, "digest": "...", "chunk_cols": 256,
                                      "chunk_index": [off, len], "nnz": 245117},
                 "cells": {"kind": 2, "off": ..., "len": ...}, "...": {...}},
     "stats": {"median_umi": ..., "median_genes": ...}}
  ],
  "legacy": {"key": "data/GSE145370/GSE145370.singlet", "etag": "...", "bytes": 187066350, "migrated_at": "...", "ledger": "..."}

```

`rev` = digest of the sorted list of sample keys plus the study-file contents; MCP and clients use it for "unchanged" answers.

## 8. Search and statistics

* **Catalog (D1):** one row per sample object (`v2_sample`: gsm, gse, key, bytes, sha256, n_columns, n_called, member offsets JSON,
  per-sample cell-stat quantiles) and per study (`v2_study`: gse, manifest key, rev, bytes). Sample-level filters (organism, tissue,
  protocol, QC, cell counts, depth quantiles) run in D1 as today.
* **Cells:** per-sample `cells` tables carry per-cell statistics; a cell query first selects samples in D1, then reads the cells tables of
  those samples (small, edge-cached) and returns `(gsm, columns)`; slicing then fetches only the chunk runs covering those columns.
* An atlas-wide cell index (columnar shards of quantised per-cell stats, `v2/cidx/`) is a later addition when cross-atlas cell queries
  need sub-second latency; the cells tables are its source of truth.

## 9. Legacy member mapping (migration)

Each legacy member maps to one v2 treatment; the migration verifies regeneration per sample and falls back to kind 3 (stored, zstd) if
the bytes differ. Recipe ids are versioned strings; the reference implementation lives in `python/singlet/v2/recipes.py` with golden
tests, the C++ readers call into the same definitions where they need them.

| legacy member | v2 treatment |
|---|---|
| `exon_counts.1pz`, `intron_counts.1pz` | pz2 matrix; names from vocabulary pack; columns from `cells` |
| `sj_counts.1pz`, `vdj_gene_usage.1pz`, `mt_heteroplasmy.1pz`, `mt_events.1pz` | pz2 matrix (inline or pack names) |
| `splice_psi.1pz` | derived from `sj_counts` by `psi-v1-rint`, `psi-v1-trunc` or `psi-v1-stub` (whichever reproduces the bytes) |
| `cell_calls.tsv` | derived from the `cells` table (`cellcalls-v1`), else stored |
| STARsolo `Gene/filtered/matrix.mtx`, `filtered/barcodes.tsv` | derived from raw matrix + called set (`mtx-filter-v1`) |
| STARsolo `Gene/raw/barcodes.tsv` | derived from the protocol whitelist pack (`whitelist-sorted-v1`) |
| STARsolo `features.tsv` (raw, filtered) | derived from the vocabulary pack (`features-v1`) |
| STARsolo `Gene/raw/matrix.mtx` | pz2 matrix (genes x raw barcodes) + `mtx-text-v1` writer recipe |
| `ambient_profile.tsv` | small integer vector member + `ambient-v1` recipe |
| `gene_expression.tsv`, `cell_qc_metrics.tsv`, per-cell TSVs | derived from matrices / `cells` columns where verified, else stored |
| `feature_vocab.json` (study level) | derived from the vocabulary pack (`vocab-json-v1`) |
| JSON members, logs, `star_SJ.out.tab`, everything else | stored (kind 3, zstd-19) |

## 10. Migration and retirement

Per study: read the live legacy bundle, decode every member, build v2, re-decode v2 and compare with the legacy content (section 1),
upload sample objects and the manifest, verify the uploaded bytes (size + MD5/ETag or SHA-256 re-read), write the ledger
(`v2/ledger/<GSE>.jsonl` and D1 `v2_migration`). After every study is migrated and clients default to v2, legacy bundles are copied to a
private archive bucket and removed from the public bucket; the archive is deleted after the grace period recorded in `docs/v2-migration.md`.
