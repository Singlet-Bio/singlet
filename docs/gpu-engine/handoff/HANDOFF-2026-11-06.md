## Goal

Make `singlet --engine gpu` turn as many samples per hour as possible into `.s1` objects on one Clipper GPU node (2 H100 NVL, 56 cores, 768 GB). The engine is a CUDA port of STAR 2.7.11b plus the pileup. The aligner and every integer path must stay byte-identical to the CPU engine. Iterative floating-point stages such as donor demux are judged by a tolerance against ground truth instead (decision by Zach, 2026-11-05).

## How the engine spends time

One process runs per sample. Reads collapse to distinct sequences and go through three device lanes: A light (`k_p1s`, `k_p3lb`), M medium (warp per read, `k_p3a`, `k_p3w`) and B heavy (`k_p3e`, thread per read). Lane B overflow goes to a host pool that runs CPU `mapRead`. A device lock with 2 slots per GPU serializes the device phase of the processes. Each process uploads its own 16.4 GB index unless the shared index is on.

At 8 samples in flight, 7 threads each and 2 slots, a node does about 1.75 M read pairs/s on g050 and about 2.4 to 2.6 on g051 with the same binary. Per run on pbmc1k_v3 the host spends about 630 core-s: demux 142, stream 170, refs 91, export 37, nonhost 45, STAR 88 (38 with e20w). The advisor's main point is that host cores bind before the GPU does.

## Method rules that hold

- **Timing:** exclusive jobs on g050 to g052, with A/B/B/A arms inside one job and a fixed b0 arm in every job. Node effects reach 35%, so compare arms only within a job.
- **Metrics:** decide on core-s/M and lock held per run, which vary about 1%. Rate varies 7.7% between legs and serves only as a confirmation. Exclude runs that start before the first completion.
- **Correctness:**
  - Identity harness against b0 and the CPU engine.
  - The 16-input code-path corpus (`bench/gpu-paths`).
  - The 10-sample gate before any merge into a release line.
  - The harness flags provenance paths, `nonhost_reads.fq` and unmapped-read files of identical size. Those are expected run-to-run differences in read order, not failures, so read the diff list before trusting a NOT IDENTICAL verdict.
- **Campaign style:** self-running Slurm chains that end in a summarizer writing `summary.md`. Use fresh, lean agents and no agent that watches jobs.
- **Commit check:** binaries built on Clipper embed only a short hash. Set `ALLOW_NO_EMBED=1` on every timing and corpus job. Six jobs died on this check on 2026-11-05.
- **GPU limit:** Clipper allows about one exclusive GPU timing job per user at a time (QOSMaxGRESPerUser), so chains run in series.
- **Clipper rules:** use the `clipper` skill. Nothing runs on the login node except sbatch and friends. Code arrives by git. Only logs and small results come back. Never print `~/.bashrc`.

## Next steps, in order

1. Read the queued summaries above. Check identity first.
2. If gpu/bold-integ holds, open a PR into perf/gpu-next once PR 194 merges, then run the 10-sample gate.
3. Add the VMM shared index to the integration branch if 800869 shows lock time per run falling without fallbacks. Re-time 3 and 4 slots with MPS.
4. Run both GPUs from one node at k=16 (800789 is the baseline). Watch host RAM. It peaks near 340 GB at k=8, so memory may cap k before cores do.
5. Cut host core-s, which the advisor ranks first:
   - adopt the demux screen if 800850 shows a gain;
   - add per-stage in-process timers for `stream` (246 core-s) and `refs` (114 core-s), since perf is unavailable;
   - the 1fq decode and the barcode histogram are the visible parts of refs.
6. Kernel work moves to lanes A and M. After WSHRINK lane B is about 4 s of a 28 to 37 s hold, while lanes A and M are about 8 s together under load. Re-profile `k_p3lb` and `k_p1s` with ncu, matching plain kernel names.
7. Donor demux: read the v2 summary, especially the ELBO diagnostic. The advisor recommends porting vireo's three-state genotype model in place of the clone model, then setting tolerances against truth. Install souporcell in a venv or with cargo if a second ceiling is wanted. Genotypes, VCFs and per-SNP counts stay on Clipper and in private objects.
8. Exact cross-sample read cache, after items 1 to 6 (design in the advisor report, section 4). Re-measure hit rates on 20 random GEO samples first.
