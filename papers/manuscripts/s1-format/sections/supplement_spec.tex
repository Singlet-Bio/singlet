\section{Format specification}
\label{spec:sec}\label{sec:spec}

This section specifies the \sone{} sample object, its members, the packs they reference and the study manifest that
lists the objects of a study. This specification is normative. The reference implementation, the header-only C++
library in the \texttt{singlet} repository and the Python package \texttt{singlet.s1}, conforms to it; a
disagreement between the two is a defect to be reported. Paragraphs marked \emph{informative} describe choices of the reference writer or reader and state no requirement.

\subsection{Conventions}
\label{spec:conv}
The key words MUST, MUST NOT, SHOULD, SHOULD NOT and MAY are to be interpreted as described in RFC~2119 when they
appear in upper case. A \emph{writer} produces objects, packs or manifests; a \emph{reader} consumes them. A reader that
\emph{rejects} a structure reports an error and returns no data decoded from it; ``rejected'' in a table states a MUST
requirement on readers.

All integers are unsigned and little-endian unless stated otherwise. $\lambda(x)=\lfloor\log_2 x\rfloor$ for $x\ge 1$.
$\mathrm{LEB}(x)$ is unsigned LEB128 (7 bits per byte, least significant group first, bit 7 set on every byte but
the last); readers MUST reject an encoding longer than 10 bytes or one that runs past its stream. The zigzag map on a
64-bit signed $d$ is $\mathrm{zz}(d)=(2d)\oplus(d\gg 63)$ (arithmetic shift). A \emph{STREAM} is
\texttt{u32 raw\_len}, \texttt{u32 zstd\_len}, then one zstd frame of \texttt{zstd\_len} bytes that MUST decompress to
exactly \texttt{raw\_len} bytes. An empty payload is stored as \texttt{0,0} with no frame; readers MUST reject a STREAM
in which exactly one length is zero. \emph{Informative:} reference writers record the content size and omit the zstd
checksum; the level (19 by default) is a writer choice, and frame bytes can differ between zstd versions.
% src: common.h:70-100 (put_stream/get_stream); util.py:81 (write_content_size=True, write_checksum=False); common.h:73 ZSTD_compress (no checksum)
CRC-32 is that of ISO~3309 and zlib (reflected polynomial \texttt{0xEDB88320}, initial value and final XOR
\texttt{0xFFFFFFFF}). $\mathrm{digest16}(b)$ is the first 16 bytes of $\mathrm{SHA\text{-}256}(b)$; \emph{hex} is
lowercase hexadecimal, so a digest16 is written as 32 hex digits. Text is UTF-8. A \emph{NUL-joined} list is the
concatenation of its strings, each followed by one zero byte; a \emph{NUL-separated} list has one zero byte between
consecutive strings and none at the end. \emph{Canonical JSON} is a JSON value encoded in UTF-8 with object keys sorted
by code point, no whitespace between tokens, and non-ASCII characters written as UTF-8 rather than escaped.
% src: common.h:24-37 (crc32); util.py:44-46 (d16), 57-64 (canon_json: sort_keys, separators (",",":"), ensure_ascii=False), 145-163 (join_nul, split_nul)

\subsection{The sample object}
\label{spec:container}
A sample object is a 64-byte file header, a member table, and the member bodies (Tables~\ref{spec:tab:filehdr}
and~\ref{spec:tab:entry}). It is immutable and content addressed: it is published under the key
\texttt{s1/s/<GSM>/<h>.s1}, where \texttt{<h>} is the hex of $\mathrm{digest16}$ of the whole object, and the study
manifest (Section~\ref{spec:manifest}) lists its length and full SHA-256.

\paragraph{Layout rules.}
The first body starts at $\lceil(64+\texttt{table\_len})/64\rceil\cdot 64$; every body starts at a multiple of 64,
in table order, separated by zero padding; the object ends at the end of the last body (no trailing padding).
A member with no body (kind 4, or an empty body) has $\texttt{off}=\texttt{len}=0$. A reader MUST reject an object
whose member table does not parse to exactly \texttt{table\_len} bytes, has duplicate names, a kind-4 entry with a body,
a body that is not 64-byte aligned, a non-empty body that starts inside the header or table, or a body that runs past
\texttt{file\_len}. Writers MUST write \texttt{meta} as canonical JSON. Decoding a body never depends on \texttt{meta};
two keys carry meaning for the logical content, \texttt{recipe} of kind 4 (Section~\ref{spec:derived}) and
\texttt{names.rows.member} of kind 1 (Section~\ref{spec:names}).

\paragraph{Derived members and recipes.}
\label{spec:derived}
A kind-4 member has no body. \texttt{meta.recipe} is a versioned recipe id (an id never changes behavior; a change of
behavior gets a new id), \texttt{meta.params} its parameters (a JSON object) and \texttt{meta.needs} its inputs (member
names, cells columns as \texttt{cells:}\emph{column}, packs as \texttt{pack:}\emph{role}, or auxiliary members named
\texttt{matrix:}, \texttt{blob:} or \texttt{vector:}\emph{name}). A writer MUST emit a derived entry only after running
the recipe on that very sample and comparing the output with the original, and stores the member (kind 3 or 5)
otherwise. \texttt{out\_len} and \texttt{crc32} describe the regenerated bytes when the comparison was byte for byte, and
are 0 when only the canonical matrix was compared (\texttt{meta.bytes\_exact} false).
% src: recipes.py:4-27; migrate.py:850-869; container.py:146-157; recipes_ctx / context.py:385-414 (regeneration)
\emph{Conformance.} Recipe semantics are outside the conformance requirements of this version: a conforming reader
need not implement any recipe. A reader that does not implement the recipe named by a kind-4 entry MUST report that
member as unavailable and MUST NOT return other bytes in its place; it MUST still read every other member, since members
of kinds 1, 2, 3 and 5 decode without recipes. A reader that does implement the recipe MAY check the result against
\texttt{out\_len} and \texttt{crc32} when they are non-zero, or against \texttt{digest}.
\emph{Informative:} Table~\ref{spec:tab:recipes} lists the recipe ids of the reference implementation.

\subsection{The matrix member}
\label{spec:pz2}
A matrix member holds one matrix in compressed sparse column (CSC) form: $m$ rows (features), $n$ columns
(barcodes or cells) and $\mathit{nnz}$ stored entries, cut into column chunks that decode independently. Offsets in
this section are relative to the member start. Byte order of the parts:
\[
\text{header (256)}\;|\;\texttt{chunk\_index}\;|\;\texttt{tables}\;|\;\texttt{rows}\;|\;\texttt{chunks}\;|\;\texttt{cols}\;|\;\texttt{kv}\;|\;\texttt{extra}.
\]
Writers pack the sections back to back without padding; a section of length 0 has the offset it would have had.
Two codecs share this container: codec 1 (lane rANS, Sections~\ref{spec:order}--\ref{spec:rans}) and codec 2
(generic, Section~\ref{spec:codec2}).

\paragraph{Chunk index.}
$\texttt{n\_chunks}+1$ records of 24 bytes: \texttt{u64 off} (relative to the start of \texttt{chunks}),
\texttt{u32 len}, \texttt{u32 first\_col}, \texttt{u64 nnz\_before}. Chunk $c$ holds columns
$[\texttt{first\_col}_c,\texttt{first\_col}_{c+1})$ and $\texttt{nnz\_before}_{c+1}-\texttt{nnz\_before}_c$ entries in
bytes $[\texttt{off}_c,\texttt{off}_c+\texttt{len}_c)$. The last record is a sentinel
$\{\texttt{chunks.len},0,n,\mathit{nnz}\}$. A reader MUST check that record 0 is $\{0,\cdot,0,0\}$, that
\texttt{first\_col} strictly increases, \texttt{nnz\_before} does not decrease, $\texttt{off}_{c+1}=\texttt{off}_c+\texttt{len}_c$,
and the sentinel. Chunks may have different widths; the chunk of column $j$ is the largest $c$ with
$\texttt{first\_col}_c\le j$ (binary search).
% src: pz2.h:252-270; container.h:76-95 (read_chunk_index), 100-102 (write)

\paragraph{Side sections.}
\texttt{tables} (codec 1 only, else empty): three STREAMs holding the tables TC, TG, TR (Section~\ref{spec:tables}).
\texttt{rows} (codec 1 only, else empty): one STREAM whose payload is $\mathrm{LEB}(\mathit{key}_0)\cdots\mathrm{LEB}(\mathit{key}_{m-1})$,
the row keys in canonical row order (Section~\ref{spec:order}); exactly $m$ values below $2^{32}$, no trailing bytes.
\texttt{cols} and \texttt{extra} hold the column and the row names, by names kind: 0 \emph{Inline}, one STREAM of the
NUL-joined names (exactly $n$, resp.\ $m$, names); 1 \emph{Pack}, the names are the pack's list in pack order, empty
section; 2 \emph{PackSubset}, one STREAM of $\mathrm{LEB}(\mathrm{zz}(i_t-i_{t-1}))$ for $t=0,1,\dots$ with $i_{-1}=0$,
name $t$ being entry $i_t\in[0,2^{32})$ of the pack's list; 3 \emph{Cells} (columns only), the barcode column of the
sample's \texttt{cells} member, empty section; 4 \emph{None}, no names. Section~\ref{spec:names} defines the list of a
pack and the barcode column. \texttt{kv} is empty or \texttt{u32 npairs} followed by one STREAM of NUL-joined
\texttt{key}, \texttt{value} strings, ascending by the bytes of the key.
% src: container.h:104-152 (names parts); api.h:80-107 (row names in extra, column names in cols, kv); rans1_enc.h:287-291 (rows)

\paragraph{Prefix and range planning.}
The \emph{prefix} is header, \texttt{chunk\_index}, \texttt{tables} and \texttt{rows}: bytes
$[0,\,256+24(\texttt{n\_chunks}+1)+|\texttt{tables}|+|\texttt{rows}|)$, the maximum end of those sections. It is all
a reader needs to plan and decode any set of columns; names and key/values lie after the chunks. To read a set $J$ of
columns a reader (i)~fetches the prefix (how much it fetches up front is a reader choice); (ii)~maps each
$j\in J$ to its chunk; (iii)~merges consecutive chunk ids into runs
$[c_0,c_1]$ (the reference client also merges runs whose gap is small); (iv)~fetches, for each run, the one contiguous
range $[\texttt{chunks.off}+\texttt{off}_{c_0},\ \texttt{chunks.off}+\texttt{off}_{c_1+1})$, shifted by the member's
offset in the object (from the member table or the manifest); (v)~decodes each chunk and keeps the wanted columns.
A chunk's column counts (Section~\ref{spec:chunk}) decode alone and give exact output sizes.
% src: pz2.h:241-246 (prefix_len), 323-330 (ColumnPlan); api.h:33-47 (plan_columns), 300-317 (column_counts), 319-372 (decode_columns)
% src: client.py:93 (PARTIAL_GAP 256 KiB), 954-970 (_runs); container.py:243 (prefetch 65536); codec.py:514
% Measured (not in the text): 179 atlas pz2 prefixes in a local cache had prefix 45-135 KB (median 90 KB), of which

\paragraph{Chunk boundaries and limits.}
A reader MUST accept any chunk with fewer than $2^{28}$ entries and MUST reject a chunk whose column counts reach
$2^{28}$ or do not sum to its count from the chunk index. Chunk widths are writer choices.
\emph{Informative:} starting at column $j$, the reference writer takes $e=\min(n,\,j+\texttt{chunk\_cols})$; if the
chunk would hold more than $B$ entries it ends instead at the last column boundary $k\le e$ that keeps at most $B$
entries, but after at least one column; it then halves the width while the chunk holds more than $2^{27}$ entries and
spans more than one column. The default budget is $B=49{,}152$ (a single column with more entries is a chunk of its own;
objects written without a budget have fixed-width chunks), and the default \texttt{chunk\_cols} is the power of two
$c\in[128,4096]$ obtained by doubling $c=128$ while $1.414\,c<49{,}152/\max(\mathit{nnz}/n,1)$ (1024 when $n$ or
$\mathit{nnz}$ is 0).
% src: pz2.h:56 (kMaxChunkNnz 2^27), 60 (kDefaultChunkNnzMax 49152); rans1.h:20 (kMaxChunkN 2^28); rans1_enc.h:176, 257-276 (plan_chunks), 312
% src: rans1_dec.h:105-106 (reader limit and sum check); common.h:132-141 (default_chunk_cols, 49152)

\paragraph{Values.}
\label{spec:values}
Both codecs code unsigned 32-bit \emph{coded values}. For value types 1--3 the coded value is the count itself;
writers MUST NOT store a value above the range of the declared type, and readers MAY omit that check. For value type 4
with \texttt{flags} bit 0 set, every entry is a non-negative integer $v<2^{24}$ whose binary32 bit pattern round-trips
(excluding \texttt{-0.0} and NaN) and the coded value is $v$; with bit 0 clear (codec 2 only) the coded value is the
binary32 bit pattern. Explicit zero values are legal in both codecs. Codec 1 accepts every coded value below $2^{32}$
and value types 1--3 or 4 with bit 0; codec 2 accepts every value type. Empty matrices ($m$, $n$ or $\mathit{nnz}$ zero)
are legal.
% src: values.h:4-8, 15-32; api.h:476-511 (analyze), 653 (rans_ok); rans1.h:14, 23-24 (classes cover every u32)
\emph{Feature limit.} Codec 1 represents at most $m=2^{21}-1=2{,}097{,}151$ rows (features). A writer MUST code a matrix
with $m\ge 2^{21}$ rows with codec 2, which accepts any $m\le 2^{32}-1$.

\subsection{Row order (codec 1)}
\label{spec:order}
Codec 1 stores rows in \emph{class order}. For canonical row $i$ with $\mathit{cnt}_i$ entries in the whole matrix
the writer stores
\begin{equation}
\mathit{key}_i=\begin{cases}
0 & \mathit{cnt}_i=0,\\
\mathit{cnt}_i & \kappa=0,\\
1+\kappa\,\lambda(\mathit{cnt}_i)+\left\lfloor \kappa\,(\mathit{cnt}_i-2^{\lambda(\mathit{cnt}_i)})/2^{\lambda(\mathit{cnt}_i)}\right\rfloor & \text{otherwise,}
\end{cases}
\label{spec:eq:key}
\end{equation}
($\kappa=\texttt{classes\_per\_octave}$, 4 by default, so four classes per doubling of $\mathit{cnt}$) in the
\texttt{rows} section. The decoder derives the permutation from the stored keys: stored id $s$ is the rank of
canonical row $i$ when rows are sorted by key descending and, within a key, by canonical id ascending (a stable sort),
and $\pi(s)=i$. Any key vector therefore defines a valid permutation, and the keys are all that is stored. Codec 1 works in
stored ids throughout. A decoder offers \emph{native} output (stored ids, ascending in every column, plus $\pi$) and
\emph{canonical} output (ids mapped through $\pi$, then each column sorted ascending; ids are unique within a column),
which is the original matrix. For codec 2 the two are identical and $\pi$ is the identity.
% src: rans1.h:258-285 (row_key, perm_from_keys: counting sort, key descending, id ascending); api.h:62-68 (keys read), 149-207 (canonicalize)
% src: pz2.h:24-27 (native vs canonical)

\subsection{Symbolization (codec 1)}
\label{spec:sym}
\paragraph{Log-linear classes.}
Every $x<2^{32}$ is split into a class $\gamma(x)\in[0,123]$ and $b(\gamma)$ extra bits:
\begin{gather}
\gamma(x)=\begin{cases} x & x<8,\\ 4\lambda(x)-4+\left(\lfloor x/2^{\lambda(x)-2}\rfloor \bmod 4\right) & x\ge 8,\end{cases}
\qquad b(\gamma)=\max(\lfloor\gamma/4\rfloor-1,\,0),\notag\\
\beta(\gamma)=\bigl((\gamma\bmod 4)+4\,[\gamma\ge 4]\bigr)\,2^{b(\gamma)},\qquad x=\beta(\gamma(x))+\epsilon,\quad 0\le\epsilon<2^{b(\gamma(x))}.
\label{spec:eq:cls}
\end{gather}
Classes 0--7 are exact, then four per octave; class 123 ends at $2^{32}-1$, so the classes cover every 32-bit value. Extra fields of up to 29 bits are coded as raw fields inside the
rANS state (Section~\ref{spec:rans}); a field wider than 16 bits is split into its low 16 bits, decoded first, and its
high $b-16$ bits.
% src: rans1.h:13-20, 22-44 (g_cls, ClsTab), 243-249 (put_bits: high part pushed first)

\paragraph{Entries to symbols.}
Walk a column's entries in ascending stored id with $P=0$ at the column start. For the entry with stored id $r$ and
coded value $v$, the gap is $g=r-P\ge0$, the flag is $\phi=[v\neq 1]$, the gap symbol is
$\sigma=2\gamma(g)+\phi\in[0,247]$ with extra bits $\epsilon(g)$, and then $P\leftarrow r+1$. If $\phi=1$ the
\emph{residual} $q=0$ for $v=0$ and $q=v-1$ for $v\ge2$ is coded as its class $\rho=\gamma(q)\in[0,123]$ and extra
bits $\epsilon(q)$. The decoder inverts this as $v=1$ if $\phi=0$, else $v=0$ if $q=0$ and $v=q+1$ otherwise. A chunk
also codes the entry count $k_j$ of each of its columns as $\gamma(k_j)$ and $\epsilon(k_j)$.
The alphabets are 124 (TC, column-count classes), 248 (TG, gap symbols) and 124 (TR, residual classes).
% src: rans1_enc.h:97-121 (scan_columns); rans1_dec.h:213-216 (value assembly); rans1.h:16 (kAlpha = 248)

\subsection{Context model (codec 1)}
\label{spec:ctx}
Contexts use only quantities the decoder knows before the symbol: the entry count $k$ of the current column and the
position reached in the stored row order. With
\begin{align}
\kappa_{\mathrm{raw}}(k)&=\lambda(k+1), \qquad d(k)=\min\bigl(\lfloor 11\,\kappa_{\mathrm{raw}}(k)/32\rfloor,\,3\bigr),\notag\\
\mathrm{pos}(p)&=2\lambda(p+2)+\left(\lfloor (p+2)/2^{\lambda(p+2)-1}\rfloor\bmod 2\right)-2 \qquad(\text{two buckets per octave of }p+2),
\label{spec:eq:posb}
\end{align}
the gap symbol of an entry is coded in TG context
\begin{equation}
\xi_G=\min\bigl(\kappa_{\mathrm{raw}}(k)\gg s_k,\ k_{\max}\bigr)\,(c_{\max}+1)+\min\bigl(\mathrm{pos}(P)\gg s_p,\ c_{\max}\bigr),
\label{spec:eq:ctxg}
\end{equation}
where $P$ is the previous stored id of the column plus one (0 at the column start) and $(s_p,c_{\max},s_k,k_{\max})$
come from \texttt{ctx\_kind} (Table~\ref{spec:tab:ctx}). The residual class of an entry with stored id $r$ is coded in
TR context
\begin{equation}
\xi_R=4\min\bigl(\lfloor\mathrm{pos}(r)/2\rfloor,\,20\bigr)+d(k)\in[0,83].
\label{spec:eq:ctxr}
\end{equation}
Column counts use the single context of TC. $\mathrm{pos}(0)=0$ and $\mathrm{pos}(r)\le 41$ for $r<2^{21}$, so the
21 position buckets of TR cover every row of a codec-1 matrix.

\subsection{rANS coding (codec 1)}
\label{spec:rans}
\paragraph{State and renormalization.}
Each coder state $X$ is a 32-bit unsigned integer kept in $[2^{16},2^{32})$; renormalization moves one 16-bit word.
To decode a symbol from a table of precision $p$ in context $\xi$, with $u=X\bmod 2^{p}$ and the symbol $s$ whose
slots $[C_s,C_s+f_s)$ contain $u$:
\begin{equation}
X\leftarrow f_s\,\lfloor X/2^{p}\rfloor+u-C_s;\qquad \text{if }X<2^{16}:\ X\leftarrow 2^{16}X+w,
\label{spec:eq:dec}
\end{equation}
where $w$ is the next unread little-endian \texttt{u16} of the stream (the \emph{refill}). A raw field of $b\le16$ bits
is $\epsilon=X\bmod 2^{b}$, then $X\leftarrow\lfloor X/2^{b}\rfloor$ and a refill; $b=0$ reads nothing. A field of
$17\le b\le 32$ bits is a 16-bit field followed by a $(b-16)$-bit field, $\epsilon=\epsilon_{\mathrm{lo}}+2^{16}\epsilon_{\mathrm{hi}}$.
One refill always restores $X\ge 2^{16}$.
\emph{Informative (encoder):} symbols are pushed in exact reverse decode order; before pushing $s$, if
$X\ge f_s\,2^{32-p}$ the encoder emits $X\bmod 2^{16}$ and sets $X\leftarrow\lfloor X/2^{16}\rfloor$; then
$X\leftarrow 2^{p}\lfloor X/f_s\rfloor+(X\bmod f_s)+C_s$. A raw field of $b\ge1$ bits emits a word when
$X\ge 2^{32-b}$ and then sets $X\leftarrow 2^{b}X+\epsilon$. Every state starts at $X=2^{16}$; the emitted words,
reversed, form the word stream and the final encoder states are stored as the decoder's initial states.
% src: rans1.h:13 (kL = 2^16), 224-256 (LockEnc: init kL, put, put_uniform, put_bits, finish); rans1_dec.h:4-15, 161 (refill)

\paragraph{Chunk stream.}
\label{spec:chunk}
Each codec-1 chunk is the byte string
\[
\mathrm{LEB}(n_{wc})\ \mathrm{LEB}(n_w)\ \ \texttt{u32}\,X^{c}\ \ \texttt{u16}\,w^{c}[n_{wc}]\ \ \mathrm{LEB}(\mathit{pp0})^{*}\ \ \texttt{u32}\,X[L]\ \ \texttt{u16}\,w[n_w].
\]
\emph{Column counts.} Starting from $X=X^{c}$ and reading the $n_{wc}$ words $w^{c}$, for each of the chunk's $n_c$
columns in order decode a TC symbol $\gamma$ ($p=12$), then $b(\gamma)$ raw bits, and set $k_j=\beta(\gamma)+\epsilon$.
Afterwards $X$ MUST equal $2^{16}$, exactly $n_{wc}$ words MUST have been read, the running sum of the $k_j$ MUST stay
below $2^{28}$, and $N=\sum_j k_j$ MUST equal the chunk's count from the index; a reader MUST reject the chunk otherwise.
% src: rans1_enc.h:168-239 (encode_chunk layout), 181-194 (counts: single lane, 12-bit TC); rans1_dec.h:59-93 (chunk_counts), 95-139 (setup_chunk)

\emph{Lanes.} The chunk's $N$ entries, in column-major stored order (element $e$), are split into $L$ contiguous
slices: with $S=\lfloor N/L\rfloor$ and $t=N\bmod L$, lane $l$ owns elements $e_0(l)=lS+\min(l,t)$ to
$e_0(l)+\mathit{cnt}(l)-1$ with $\mathit{cnt}(l)=S+[l<t]$, and the chunk takes $\mathit{steps}=S+[t>0]$ steps. A slice
may start inside a column and may span several columns. For lane $l$ with $\mathit{cnt}(l)>0$ let $j$ be the column
holding $e_0(l)$ and $o$ the offset of $e_0(l)$ in it. The lane starts with $\mathit{rem}=k_j-o$, column count
$k=k_j$ (contexts always use the full count of the column), and $P=\mathit{pp0}$ if $o>0$, else 0. The $\mathit{pp0}$
values (the stored id of the previous entry of that column, plus one) are stored for the lanes with $o>0$, in ascending
lane order. The lane's initial state is $X[l]$; lanes with $\mathit{cnt}(l)=0$ keep $X[l]=2^{16}$, and all $L$ states
are present even when $N=0$. The bytes after the $\mathit{pp0}$ values MUST hold at least $4L+2n_w$ bytes.

\emph{Decode schedule.} For $s=0,\dots,\mathit{steps}-1$, the phases below run in this order, each visiting lanes
$l=0,\dots,L-1$ in ascending order and skipping lanes with $s\ge\mathit{cnt}(l)$; every operation is followed at once
by its refill, so the shared word stream is consumed in (step, phase, lane) order:
\begin{enumerate}\setlength{\itemsep}{0pt}
\item[A] decode $\sigma$ from TG in context $\xi_G$ (Eq.~\ref{spec:eq:ctxg}) with $p=p_b$; $\gamma=\lfloor\sigma/2\rfloor$, $\phi=\sigma\bmod2$;
\item[B] read $\min(b(\gamma),16)$ raw bits; \textbf{B2} if $b(\gamma)>16$, read $b(\gamma)-16$ more; then $r=P+\beta(\gamma)+\epsilon$;
\item[C1] if $\phi$: decode $\rho$ from TR in context $\xi_R$ (Eq.~\ref{spec:eq:ctxr}, with this $r$) with $p=p_v$;
\item[C2] if $\phi$: read $\min(b(\rho),16)$ raw bits; \textbf{C3} if $\phi$ and $b(\rho)>16$, read $b(\rho)-16$ more; $q=\beta(\rho)+\epsilon$;
\item[E] emit stored id $r$ and value $v$ at element $e_0(l)+s$; $P\leftarrow r+1$; $\mathit{rem}\leftarrow\mathit{rem}-1$; if $\mathit{rem}=0$ and $s+1<\mathit{cnt}(l)$, move to the next column with $k>0$: $\mathit{rem}\leftarrow k$, $P\leftarrow0$.
\end{enumerate}
B2 and C3 are separate phases (all lanes' B before any lane's B2). Afterwards the word pointer MUST be exactly at the
end of $w[n_w]$ and every state MUST equal $2^{16}$; a reader MUST reject the chunk otherwise, and MAY stop decoding as
soon as the pointer passes the end. A reader MUST reject a decoded id $r\ge m$ before using it as an index
(Table~\ref{spec:tab:integrity}). Writers MUST NOT leave bytes after $w[n_w]$; readers MAY ignore such bytes.
% src: rans1_dec.h:4-15 (normative loop), 23 (kPad 1024), 143-234 (scalar reference), 229-233 (end checks); api.h:251-258 (padding, check), 158 (id < m, canonical only)
% src: rans1_enc.h:208-230 (encoder: steps descending; phases C3,C2,C1,B2,B,A; lanes descending)

\paragraph{Frequency tables.}
\label{spec:tables}
The \texttt{tables} section holds three STREAMs, TC then TG then TR. Each payload is $\mathrm{LEB}(n_{\mathrm{used}})$
followed, for each used context $\xi$ in increasing order, by $\mathrm{LEB}(\xi-\xi_{\mathrm{prev}})$,
$\mathrm{LEB}(n_{\mathrm{sym}})$ and, for each symbol with non-zero frequency in increasing order,
$\mathrm{LEB}(s-s_{\mathrm{prev}})\,\mathrm{LEB}(f_s)$, with $\xi_{\mathrm{prev}}=s_{\mathrm{prev}}=0$ before the first.
A reader MUST reject: $n_{\mathrm{used}}$ above the context count; a zero delta after the first context or symbol; a
context or symbol out of range; $n_{\mathrm{sym}}=0$ or above the alphabet size; $f_s=0$ or $f_s>2^{p}-1$; or
frequencies of a context that do not sum to exactly $2^{p}$. $C_s$ is the sum of the frequencies of the smaller symbols
of the context. Contexts not listed have no symbols; a valid stream never uses them.
% src: rans1.h:162-181 (serialize_tables), 183-222 (parse_tables and its checks), 186 (decode entry sym<<24 | freq<<12 | bias)
\emph{Informative (quantization):} the writer counts symbols over the whole member, then for counts $c_i$ with total
$T$ sets $f_i=\max(1,\lfloor c_i2^{p}/T\rfloor)$ for $c_i>0$; while $\sum f<2^{p}$ it adds one to the first symbol
maximizing $c_i(\ell(f_i+1)-\ell(f_i))$, while $\sum f>2^{p}$ it removes one from the first symbol with $f_i>1$
minimizing $c_i(\ell(f_i)-\ell(f_i-1))$, where $\ell$ is a fixed Q32 table of $\log_2$ and the products are compared in
IEEE-754 binary64. A context with a single symbol $s$ gets $f_s=2^{p}-1$ and frequency 1 for symbol 0 (or 1 if $s=0$).
% src: rans1.h:76-94 (lg_table), 97-135 (normalize_freqs; double gains), 143-161; rans1_enc.h:315-333 (histograms over all chunks)

\subsection{Codec 2 (generic fallback)}
\label{spec:codec2}
Codec 2 stores canonical row ids ($\texttt{row\_order}=0$; \texttt{tables} and \texttt{rows} empty). A chunk is three
STREAMs: \emph{counts}, $\mathrm{LEB}(k_j)$ for each column; \emph{gaps}, for each column and entry
$\mathrm{LEB}(r-r_{\mathrm{prev}}-1)$ with $r_{\mathrm{prev}}=-1$ at the column start; \emph{values}, $\mathrm{LEB}(v)$
per entry for value types 1--3 and for type 4 with \texttt{flags} bit 0, or the 4-byte bit pattern of each value
otherwise. A reader MUST check that the counts sum to the index count, every id is below $m$, every count and value is
below $2^{32}$, no stream payload has trailing bytes, and (raw f32) the value stream has $4N$ bytes.
\emph{Informative:} with codec \texttt{auto} the writer uses codec 1 when $m\le2^{21}-1$ and the values are not raw
f32; it also builds the codec-2 member when the codec-1 member is smaller than 65{,}536 bytes and keeps whichever is
strictly smaller. Codec 2 is used otherwise.

\paragraph{Integrity of codec-2 chunks.}
A codec-2 chunk has no checksum and no end state, and its zstd frames are written without the zstd content checksum.
What applies to it is the STREAM length rules (each frame MUST decompress to exactly its \texttt{raw\_len}), zstd's own
frame validation, LEB128 bounds, and the checks above. These detect truncation, a change of any length field, and
corruptions that break the LEB128 or zstd structure or produce an id of $m$ or more. A corruption inside a frame that
still decodes to well-formed streams of the stated lengths yields wrong ids or values that only the canonical digest
(Section~\ref{spec:digest}) detects.

\label{spec:digest}

\subsection{Packs}
\label{spec:packs}
Gene vocabularies, barcode whitelists and the splice-junction table are shared between samples in immutable
\emph{packs}, published as \texttt{s1/ref/<id>.pack}. A pack file is magic \texttt{SPK2}, \texttt{u16 version} (1; other
values rejected), \texttt{u16 kind}, \texttt{u32 header\_len}, the header (a canonical JSON object of
\texttt{header\_len} bytes) and the body (the rest of the file). The pack id is $\mathrm{digest16}$ of the whole file.
Kinds: 1 row vocabulary, 2 barcode whitelist, 3 composite vocabulary, 4 junction segment, 5 junction table version.
Each body is selected by the header field \texttt{coder} (kinds 1, 3, 4); a reader MUST reject an unknown kind or coder.

\paragraph{Resolution.}
A matrix stores the first 8 bytes of a pack id, and a mode-1 barcode column the same; a pack that references another
pack stores its full 16-byte id. A reader resolves a prefix to the unique pack whose id starts with it (ambiguity is an

(and, after a download, its SHA-256 and length against the index). The index is a JSON object \{\texttt{format}:

\paragraph{Integer streams.}
Pack bodies use three containers. A \emph{P-stream} is \texttt{u8 mode}, \texttt{u32}~$n$, \texttt{u32 clen} and one
zstd frame of \texttt{clen} bytes whose payload is $\mathrm{LEB}$ of the $n$ values (mode 0) or four byte planes of $n$
bytes each, byte 0 of every value first (mode 1). A \emph{P-blob} is \texttt{u32 clen} and one zstd frame of
\texttt{clen} bytes. A \emph{J-stream} is \texttt{u8}~$w\in[1,4]$, \texttt{u32}~$n$, \texttt{u32 clen} and one zstd
frame whose payload is exactly $wn$ bytes: $w$ byte planes of the 32-bit values, low byte first; readers MUST reject
another $w$ or payload length. In J-streams, $\mathrm{zz}_{32}(d)=(2d\bmod 2^{32})\oplus(d\gg 31)$ for a 32-bit signed
$d$, and differences are taken modulo $2^{32}$.
% src: packs.py:95-123 (_pack_stream/_unpack_stream, _pack_blob/_unpack_blob); junctions.py:159-193 (_enc_stream/_dec_stream, _zigzag)

\paragraph{Row vocabulary, coder \texttt{SVP0} (kind 1, \texttt{member} \texttt{exon}).}
The header holds \texttt{build}, \texttt{member}, \texttt{coder}, \texttt{n} (exon names), \texttt{n\_genes},
\texttt{n\_intron} and \texttt{sha256\_names} (hex SHA-256 of the NUL-joined exon names). The body is: ASCII
\texttt{SVP0}; \texttt{u16} version 1, \texttt{u16} flags 0, \texttt{u8 prefix\_len}, \texttt{u8 width}, \texttt{u16}
$C$ (chromosomes), \texttt{u32}~$G$ (genes), \texttt{u32}~$E$ (exons); \texttt{u8 build\_len} and the build string;
the gene-id prefix (\texttt{prefix\_len} bytes); the schema version (8 bytes, NUL padded); then in order the P-stream
$d$ ($G$ values), the P-blob of gene kinds ($G$ bytes), the P-blob of the NUL-separated explicit symbols, the P-blob of
the $C$ NUL-separated chromosome names, and the P-streams \texttt{gch} ($G$), \texttt{nex} ($G$), \texttt{gstart} ($G$),
\texttt{elen} ($E$) and \texttt{egap} ($E-G$), with no trailing bytes. A reader MUST reject counts that differ from
$G$, $E$ and $C$. Gene $g$ has number $u_0=d_0$, $u_g=u_{g-1}+d_g+1$, gene id $I_g$ = prefix followed by $u_g$ in
decimal, left-padded with zeros to \texttt{width} digits, chromosome $c_g$ = chromosome name \texttt{gch}$_g$, and
$\texttt{nex}_g+1$ exons. Its symbol $y_g$ is empty (kind 0), $I_g$ (kind 1) or the next explicit symbol (kind 2,
taken in gene order). Exons are numbered across genes in gene order; the first exon of gene $g$ starts at
$\texttt{gstart}_g$, exon $e$ ends at $t_e=s_e+\texttt{elen}_e$, and the next exon of the same gene starts at
$t_e+\texttt{egap}$, the \texttt{egap} values being taken in order for every exon except the last of each gene. With
$H_g=I_g$\texttt{\_}$y_g$\texttt{\_}, an optional tag $\tau$ (empty here) and decimal integers, the name of exon $e$
of gene $g$ is $H_g\,\tau\,c_g$\texttt{:}$s_e$\texttt{-}$t_e$ and the name of the intron after it is
$H_g$\,\texttt{intron\_}\,$\tau\,c_g$\texttt{:}$t_e$\texttt{-}$(t_e+\texttt{egap}_e)$. The pack's \emph{exon list} is
every exon name in exon order, its \emph{intron list} every intron name in the same order, and its \emph{gene table}
the pairs ($I_g$, $y_g$ for kind 2, else $I_g$).

\paragraph{Barcode whitelist (kind 2).}

\paragraph{Junction table (kinds 4 and 5).}
\label{spec:junctions}
A junction is $(\mathit{chrom},\mathit{start},\mathit{end})$ with the intron $[\mathit{start},\mathit{end})$ in
0-based coordinates; its name is \emph{chrom}\texttt{:}\emph{start}\texttt{-}\emph{end} in decimal. A \emph{segment}
(kind 4, \texttt{coder} \texttt{JX1}; header \texttt{build}, \texttt{coords}, \texttt{id\_lo}, \texttt{n},
\texttt{tier}, \texttt{chroms}) holds table ids $[\texttt{id\_lo},\texttt{id\_lo}+n)$ in genomic order. Its body, a
\emph{segment body}, is \texttt{u32}~$n$ and six J-streams: chromosome runs (pairs of an index into \texttt{chroms} and
a row count), start differences ($\mathit{start}_i-\mathit{start}_{i-1}$, $\mathit{start}_{-1}=0$), lengths
($\mathit{end}-\mathit{start}$), attributes (bits 0--1 strand: 0 unknown, 1 $+$, 2 $-$; bits 2--4 splice motif; bit 5
annotated; bit 6 donor and bit 7 acceptor at an annotated exon boundary), genes ($\mathrm{zz}_{32}$ of the differences
of gene index $+1$ into the build's gene table, 0 for none, starting from 0), and transcript counts (saturating at
255). The run counts MUST sum to $n$. A \emph{version} (kind 5; header \texttt{build}, \texttt{version}, \texttt{n},
\texttt{segments}; empty body) lists segments \{\texttt{id}, \texttt{id\_lo}, \texttt{n}, \texttt{tier},

never changes meaning. Table id $t<n$ is row $t-\texttt{id\_lo}$ of the segment that holds it; a reader fetches that
segment by its full id and MUST check its digest16.

\subsection{Versioning and compatibility}
\label{spec:versions}
The digit \texttt{2} in the magics \texttt{SINGLET2}, \texttt{PZ2M}, \texttt{SPK2} and \texttt{CEL2} marks the container
generation (generation 1 is the legacy \texttt{.singlet} bundle); a different magic is a different format. Within a
generation each structure carries its own \texttt{u16} version, currently 1 everywhere: the file header, the matrix
member, the pack wrapper and the cells table. JSON documents carry an integer version: \texttt{manifest\_version} of the
study manifest and \texttt{version} of the pack index. A reader MUST reject a structure whose binary version it does
not know, a manifest whose \texttt{manifest\_version} is above the highest it supports, and an unknown codec id, value
type, names kind, pack kind, pack coder, cells \texttt{dtype} or barcode mode. Writers MUST write reserved bytes and
unassigned flag bits as zero; readers MAY ignore them.

\paragraph{Forward compatibility.}
The member-table entry has the same layout for every kind, so a reader can parse an object that contains members of a

\subsection{Integrity}
\label{spec:integrity}
Three notions are kept apart. \emph{Object identity} establishes which bytes are meant: a sample object is named by the
digest16 of all its bytes and listed in the manifest with its length and SHA-256; a pack is named by the digest16 of
its file and listed in the pack index with its length and SHA-256. \emph{Byte integrity} establishes that bytes read
are the bytes written: CRC-32 of the matrix member header and of regenerated bytes, the structural checks, and the
end-state checks of codec 1. \emph{Logical integrity} establishes that the decoded content is the content the writer
encoded: the canonical matrix digest (Section~\ref{spec:digest}) and the cells-table digest (Section~\ref{spec:cells}),
which cover values, names and key/values. The \texttt{digest} fields of the member table, the manifest and the matrix
header \emph{name} logical content; comparing them identifies the matrix being read and checks none of its bytes.
Version~1 has no per-chunk checksum and no checksum of the file header, the member table, the side sections or the
cells table; its zstd frames carry no content checksum. Table~\ref{spec:tab:integrity} lists each mechanism.

\paragraph{What the end-state check detects.}
An error in an initial state, or in a word bit consumed by a symbol decode, makes the decode diverge and is detected
unless all $L$ final states happen to equal $2^{16}$ with the word count matching (the probability of a miss is not
quantified). The check misses: (i)~an error in a word bit consumed by a raw field, which is shifted out of the
state unchanged: a residual extra bit (counts of 9 and above) changes only the value; a gap extra bit changes the stored
id and every later id of that lane in that column, and escapes whenever the position contexts of the following symbols
are unchanged; (ii)~errors in the $\mathit{pp0}$ values (not entropy coded; they shift the ids of a lane's first
column); (iii)~errors in the row keys, which always give a valid permutation; (iv)~errors in names and key/values;
(v)~any error in a chunk with $N=0$. Codec-2 chunks have no end state (Section~\ref{spec:codec2}).
% src: rans1_dec.h:171-178, 199-212 (raw fields leave the state); 126 (pp0 read raw); api.h:68 (any keys -> perm); 258 (N == 0 skips the kernel)

\paragraph{Full and partial reads.}
A reader that holds the whole object can verify all three notions. A range (partial) reader that fetches a matrix
member's prefix and some chunk runs can verify the header CRC, the structure of the chunk index, tables and row keys,
the structural and end-state checks of every chunk it decodes, and that the header digest equals the manifest's
(identity). It cannot verify the object digest16 or SHA-256, the canonical matrix digest or the cells-table digest,
which need bytes it does not fetch, and it cannot detect errors (i)--(v) in the bytes it read, errors in the file
header or member table (the reference client takes offsets from the manifest and does not read the table), errors in a
cells-table column that still decodes to \texttt{n\_rows} values, or wrong ids or values in a codec-2 chunk whose
streams stay well formed. \emph{Informative:} the reference client also checks the status and \texttt{Content-Range}
of every ranged response against the manifest's object length.

\subsection{Decoder implementations}
\label{spec:simd}
The scalar loop of Section~\ref{spec:chunk} defines codec-1 decoding. A decoder MAY use any instruction set or degree
of parallelism (scalar code, AVX2, or other vector instructions); every decoder MUST produce the same stored ids,
values and column counts as that loop for every valid stream, and the same accept or reject decision for every input.
All codec-1 arithmetic is on 32-bit unsigned integers; $\lambda(\cdot)$ in $\mathrm{pos}$ and $\kappa_{\mathrm{raw}}$ MAY
be computed by any exact method, for example from the exponent of an integer-to-binary32 conversion, which is exact
below $2^{24}$ (valid streams stay below $2^{21}+2$). All decoders support $L\in\{16,32,64\}$.
% src: rans1_dec.h:4-15, 143-234 (scalar reference); rans1_avx2.h:1-5 (bit-exact with decode_chunk_scalar), 39-42 (posb via cvtepi32_ps), 175-178 (kraw via exponent), 255-257 (end checks)

\emph{Informative.} The reference library contains the scalar loop and an AVX2 kernel; the AVX2 kernel needs AVX2,
BMI2 and POPCNT and the YMM state enabled by the operating system ($\mathrm{XCR0}\wedge\texttt{0x6}=\texttt{0x6}$), and
uses gathers, \texttt{vpermd} refills through a lookup table and \texttt{vcvtdq2ps} for $\lambda$. Kernels are
compiled with per-function target attributes, so no architecture flag is needed, and the fastest kernel the CPU
supports is chosen at run time. \texttt{PZ2\_ISA=scalar} or a per-call option selects the scalar loop; on non-x86 targets
or with \texttt{PZ2\_SCALAR\_ONLY} only the scalar loop exists. SHA-256 for the canonical digest has a separate path
for the x86 SHA extensions, chosen at run time and disabled by \texttt{PZ2\_ISA=scalar}.
