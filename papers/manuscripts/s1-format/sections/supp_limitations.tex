\section{Limitations in detail}
\label{sec:slimits}

\begin{itemize}\itemsep 1pt
\item \emph{Hardware.} All timings come from 8 cores of shared cluster nodes of one type, three repeats per
  configuration, with a RAID controller cache that cold reads cannot clear. Absolute rates depend on the CPU and disk; the
  conclusions rest on comparisons made on the same node and file. AVX-512 was not measured (the CPU lacks VBMI2), and
  processors without AVX2, including ARM, use the scalar decoder at about a third of the AVX2 rate per core.
\item \emph{Large matrices.} Above $4\times10^8$ non-zeros a subset of formats was timed, at one thread count and from
  local disk. RDS and BPCells are not applicable above $2^{31}-1$ non-zeros because the benchmark reads them into a
  \texttt{dgCMatrix}; BPCells itself streams larger matrices. A genome-wide Perturb-seq screen (6.3 billion non-zeros)
  was excluded because writing the comparison formats exceeded the campaign's memory and time.
\item \emph{Networks.} The emulated tiers have a shared bandwidth limit and fixed added latency, and the 10\,Gbit/s tier
  exceeds what the setup delivers. The one real store, R2 through a Worker, was read from one node over one path at one
  time of day; prices are list prices without free tiers or discounts.
\item \emph{Baselines.} The generic-codec control at \sone's granularity is one configuration (sharded Zarr v3, Blosc
  zstd with bit shuffling); zstd with a per-matrix dictionary and stronger count models were not tested, and the payload
  ladder does not separate gene reordering, context modelling and the entropy coder.
\item \emph{Scope.} \sone{} stores non-negative integer counts below $2^{32}$; the writer rejects non-integer matrices,
  which excluded one candidate dataset (the container's generic codec for floating-point values was not evaluated).
  Richer annotations (AnnData's \texttt{obs}, \texttt{var}, \texttt{obsm}, \texttt{uns}) are not part of the format.
  Reading one gene across all cells needs a full decode, and adding cells means writing a new immutable object.
\item \emph{Decoding speed per core.} One core keeps up with about \nm{kern-s1-knee-gbit}\,Gbit/s of link, a fraction
  of byte- and bit-aligned codes and zstd (Fig.~\ref{M-fig:floor}b). Above about \nm{frac-cross-gbit}\,Gbit/s per decoding
  core a larger but faster code delivers more (Fig.~\ref{M-fig:floor}c). The textbook codes are our own AVX2
  implementations (zstd is the library), so tuned libraries and other processors may shift them. The trend of
  Fig.~\ref{M-fig:floor}b is an empirical fit to a few code families, extrapolated beyond the smallest; it is not a bound,
  and leaving out any one code moves \sone's ratio to it between \nm{trend-s1-loo-lo} and \nm{trend-s1-loo-hi}\%.
\item \emph{Writing.} Write cost was measured once on each of three matrices already in memory; converting from a file
  adds that format's read. The \sone{} writer needed about three times AnnData's memory beyond the input on the largest.
\item \emph{One implementation.} \sone{} has one implementation, in C++ with Python and R bindings.
\end{itemize}
