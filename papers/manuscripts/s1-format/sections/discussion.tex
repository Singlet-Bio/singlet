\section{Discussion}
\label{sec:discussion}

Single-cell count matrices have been stored as generic arrays, handed to compressors that cannot see what the bytes mean.
\sone{} instead describes the counts with what is known about them, and this one change makes files several times smaller
than the formats in common use while keeping them among the fastest to read. The comparison with count models shows that
the remaining margin for any lossless format of this kind is small: most of what is left in UMI data is the random sampling
of molecules itself.

The practical consequences follow from where data are read. Atlases and model-training pipelines increasingly keep data in
cloud object storage and read the same cells many times. There, the size of each minibatch on the wire, the number of round
trips needed to fetch it and the per-request and egress fees set both the speed and the cost of every epoch. A format that
is small, fast to decode and readable in part moves the bottleneck from storage back to the model: in our measurements a
training loader could start from a remote \sone{} file in under a second and keep a typical network link busy without
downloading or converting anything first. Storage itself shrinks in proportion to file size, and because each sample file is
named by a hash of its contents, a link or a citation identifies exactly the bytes that were analysed, which helps make
analyses reproducible. The same structure, many small counts with heavy-tailed frequencies, is found outside single-cell
biology; on bulk RNA-seq counts and on a text corpus stored as word counts, \sone{} files were also less than half the size
of compressed AnnData (Supplementary Section~\ref{sec:beyond}).

Our study has limitations (Supplementary Section~\ref{sec:slimits}). All timings come from one type of cluster node, so
absolute rates will differ on other hardware, although the comparisons between formats were made on the same node and
files. The network experiments used an object store with controlled bandwidth and latency, and the one real cloud store was
read from one location; other providers and paths will differ. Kernels for AVX-512 and ARM processors were not measured. The
\sone{} writer needs more memory than most formats. The format stores whole-number counts only and does not hold the rich
cell and gene annotations of an AnnData object, and it has a single implementation, for which the specification in the
Supplement is meant to make a second possible.

As single-cell data continue to grow and move to the cloud, how they are stored becomes part of how fast and how cheaply
they can be used. \sone{} shows that a format designed around the data can be at once smaller, faster and directly readable
over a network, and the \texttt{singlet} package makes it available today from Python, R and C++.
