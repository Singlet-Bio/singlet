# E1: how much of a cell is predictable from the rest of the cell?

Status: measurements complete for all 14 files at interval and gene resolution, plus a calibration extension and a
learning curve on three files. The E1 agent stopped on an API rate limit before writing this note; it was written
afterwards from its result files by the coordinating session. Plan: `plans/E1_split_predictability.md`.
Theory context: `notes/theory_fable.md` sections 1-3.

Sources (all in `results/`): `e1_summary.tsv`, `e1_summary_gene.tsv` (per-file ladder), `e1_tables.md` (full
tables, generated by `tools/e1_tables.py`), `e1_cal_report.md` (calibrated predictors and mixtures),
`e1_afrac_report.md` (learning curve over the context share), `e1_hpi.tsv` (per-cell expression entropy),
`e1_split*.tsv` (raw rows). Code: `tools/e1_split.py`, `e1_cal.py`, `e1_hcurve.py`, `e1_report.py`, `e1_tables.py`.

## What was measured

Each called cell's UMIs were split at random into halves A and B (per unit of count). The held-out half B was scored
under a ladder of predictors that never see B: L1 = file-level per-feature × depth-bucket model (leave-one-cell-out);
L2 = L1 shrunk toward the mean profile of the cell's nearest neighbours, located from A alone; L3 = Dirichlet posterior
combining a prior with the cell's own A counts; L3dm = the same with an exact Dirichlet-multinomial count model
(within-cell burstiness); L4 = an in-sample oracle, biased low by construction and not a reachable number.
Hyper-parameters were cross-fitted over cells. Up to 5,000 random called cells per file (2,000 at gene level).

## Result 1: the state term is small

Gains over L1 at interval resolution. "per held-out nnz" is the unit of the ladder; "per cell nnz" divides the
bits saved per cell by the cell's whole nonzero count, which is the unit a codec pays in.

| pbmc_v2_typical exon | 717 | 5.68 | +0.07 | +0.04 | 23 |
| pbmc_v2_shallow exon | 76 | 7.18 | 0.00 | 0.00 | 0 |
| pbmc_v3_lowgenes exon | 306 | 5.33 | +0.20 | +0.12 | 28 |
| pbmc_v3_lowgenes intron | 109 | 6.87 | +0.59 | +0.35 | 37-48 |
| tcell_5p exon | 1152 | 6.06 | +0.10 | +0.06 | 43 |

| brain_sn_v3_deep exon | 1044 | 7.18 | +0.07 | +0.04 | 42 |

At gene resolution the gains are somewhat larger (0.09-0.27 per held-out nnz on the dense exon files, 0.21 on
brain_sn_v3_deep intron) but still small. The calibrated extension, which repairs the baseline by expression level
and learns an explicit A-to-B map, mixed with neighbours, gains 0.00-0.21 bits per held-out nnz over the repaired
baseline on every file except pbmc_v3_lowgenes intron (0.48).

## Result 2: neighbours carry it; the cell's own other half does not

L2 (neighbours) accounts for nearly all of the best gain on every deep file. L3seq (own half only) adds 0.000 on
brain_sn_v3_deep exon and 0.02-0.07 on the PBMC and T-cell files. The learning curve confirms this: with the
context share f moved from 0.25 to 0.75, the gain per held-out nonzero barely moves (brain_sn_v3_deep exon
0.055 → 0.075; pbmc_v2_typical exon 0.076 → 0.058). Seeing more of the cell does not help, because the cell's
idiosyncratic features are seen once and never again.

## Result 3: the one outlier is burstiness, not cell state

pbmc_v3_lowgenes intron (a degenerate library with 2,642 genes detected) is the only file with a gain above 0.3 per
cell nonzero. Most of it is the Dirichlet-multinomial count model (full-cell burstiness gain 0.47 bits/nnz), and the
empty-droplet control shows the same effect (0.81). That is molecule-level clumping of UMIs, which a clumped count
model captures in any column; it is not cell-type information.

## Result 4: where the sampling floor sits

The coverage-adjusted (Chao-Shen) estimate of each cell's own expression entropy gives a sampling floor of 3.4-7.6
bits per held-out nonzero against L1's 5.3-10.0. The gap between the two is the information each cell carries about
its own expression profile. Result 1 shows that at most 0.0-0.2 bits of it is predictable from anything a decoder
can have decoded first; the rest is unique to the cell. For a lossless code it is information, not redundancy, and
the reachable floor for a decoder that knows only the reference and the file is L1 minus the Result 1 gains.

## Verdict against the plan's anticipated result

The plan anticipated a 0.5-1.5 bits/nnz gain for PBMC-depth cells and k_eff of 50-100. Measured: 0.04-0.12 bits
per cell nonzero on typical files and k_eff of 0-62 (median about 20). The state term is in the lowest part of the
range the theory allowed. **A per-feature × depth adaptive coder is within about 0.1 bits/nnz (1-2%) of everything
an in-file model can reach on called cells**, apart from degenerate libraries where a clumped count model is worth
up to 0.5. Neighbour conditioning, not sequential within-cell conditioning, is the right shape for that last 1-2%.
This implies the within-cell hub-gene coder (`w3_coexp`) will not reach its 0.3 bits/nnz go threshold on the PBMC
and T-cell files.
