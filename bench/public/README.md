# Singlet 1.0.0 public benchmark program

This directory holds everything behind singlet.bio/benchmarking: the cohort, the results contract, the harness that
produces every published number on Clipper, and the notebook that reproduces them.

| path | what |
|---|---|
| `CONTRACT.md`, `contract.py`, `schema/` | results contract 1.0.0: one JSON per capability plus an index. `contract.py` is the validator, pass-rule evaluator, index builder and diff (stdlib only) |
| `cohort.tsv`, `cohort.md`, `make_cohort.py`, `cohort_plan.py` | the cohort (37 datasets, verified accessions, truth, licence, size), why each dataset is there, and the compute budget |
| `harness/` | Clipper / Slurm: `setup.sbatch` (one-off), `submit.sh` (fetch, every dataset x tool run, collect), `run.sbatch`, `fetch.sbatch`, `collect.sbatch`, `provenance.py`, `tools/<tool>.sh` hooks for owners' tools |
| `capabilities/<id>.py` | `compute(artifact_dir) -> document` per capability. The harness and the notebook call the same function |
| `run_capability.py` | runs a compute module, validates the result, writes it or diffs it against a published file |
| `sexancestry/` | the chromosomal-sex and genetic-ancestry benchmarks (owned here): geo_sex21 + cellXY, MAGE + somalier/peddy |
| `notebook/` | `singlet_benchmarks.ipynb` (generated by `make_notebook.py`) and `requirements.txt`, offered for download on the page |
| `results/` | published documents and `index.json`: pulled from Clipper, JSON only |

## For capability owners

1. Read `CONTRACT.md`. Your capability id is in its section 1.
2. Choose datasets from `cohort.tsv`. To add one, edit `make_cohort.py` and regenerate.
3. Deliver `results/<id>.json`. Either:
   - write `capabilities/<id>.py` (`compute`), optionally with `<id>_prepare.py` (`prepare(runs_dir, artifact_dir,
     resources)`) so that `collect.sbatch` builds your artifacts from the harness runs; or
   - drop a finished document in `$WORK/bpub/results-incoming/<id>.json` on Clipper.
4. Check it with `python bench/public/contract.py validate bench/public/results/<id>.json --cohort bench/public/cohort.tsv`.
5. Non-core tools run through `harness/tools/<tool>.sh <dataset> <outdir> <libs.tsv>`. `run.sbatch` exports the
   variables these hooks need.

## On Clipper

All paths are under `$WORK/bpub`; `$WORK/bench-public` belongs to another session.

```bash
sbatch --partition=scavenger --requeue bench/public/harness/setup.sbatch   # once: branch, readers, whitelists, cellXY, somalier, peddy
bash bench/public/harness/submit.sh --tier core                            # about 19 h at 12 concurrent tasks
bash bench/public/sexancestry/submit_sex.sh
bash bench/public/sexancestry/submit_ancestry.sh
```

The Singlet binary under test is `$PB/bin/singlet-campaign` (PGO build of `prod/campaign` 02aa9b9, PR #31), unless `SINGLET_BIN` is set.
Its sha256 and source commit are written to `$WORK/bpub/singlet_binary.json`. 10x comparisons (Cell Ranger, ARC, ATAC,
vdj, Space Ranger) use the outputs 10x published with each dataset (Zach, 2026-10-25); `CELLRANGER` enables a real run
later.
