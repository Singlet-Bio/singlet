# Public benchmark results contract (schema 1.0.0)

This contract is how every Singlet 1.0.0 benchmark reaches singlet.bio/benchmarking. Each capability writes one JSON
file. The website, the notebook and CI read only these files.

| | |
|---|---|
| one file per capability | `bench/public/results/<capability>.json` (`schema: "singlet.benchmark.capability"`) |
| index | `bench/public/results/index.json` (`schema: "singlet.benchmark.index"`), generated by `contract.py index`, never by hand |
| reference implementation | `bench/public/contract.py`, standard library only (`validate`, `evaluate_metric`, `capability_status`, `build_index`, `diff`) |
| JSON Schemas (for the website) | `bench/public/schema/capability.schema.json`, `bench/public/schema/index.schema.json` |
| worked example | `bench/public/schema/example-capability.json` (validates; not a real result) |
| cohort | `bench/public/cohort.tsv`: every `datasets[].id` must be a row there |

**Versioning.** `schema_version` follows semver. A minor version adds optional fields and existing readers keep
working. A major version is a breaking change, and `validate()` rejects documents from another major version. Change
this file, `contract.py` and the schemas together, in one commit.

**Validity.** A document is valid when `python bench/public/contract.py validate <file> --cohort bench/public/cohort.tsv`
prints `OK`. CI runs the same check (`tests/python/test_bench_public_contract.py` checks the example and every file in
`results/`).

## 2. The capability document

Top-level fields (all required unless marked optional):

| field | type | notes |
|---|---|---|
| `schema` | `"singlet.benchmark.capability"` | |
| `schema_version` | string | `"1.0.0"` |
| `capability` | id | from section 1 |
| `title` | string | page heading, e.g. "Chromosomal sex" |
| `conclusion` | string, at most 100 words | the claim the page leads with; state numbers, name competitors |
| `methods` | markdown, at most 400 words | data, truth, how each tool was run, how metrics are computed |
| `status` | `"draft"` or `"final"` | only `final` documents can pass |
| `generated_at` | ISO 8601 | |
| `owner` | string | session or person responsible |
| `singlet` | object | `version` ("1.0.0"), `commit` (40-hex SHA of the binary's source), optional `branch`, `binary`, `binary_sha256`, `build_flags` |
| `tools` | list | every program in the comparison: `name`, `version`, `role` (`singlet` / `competitor` / `truth` / `helper`), optional `url`, `citation`, `params` (exact command line or settings) |
| `datasets` | list | `id` (cohort id), `accessions` {`gse`, `gsm`[], `srr`[], `url`, `other`[]} (at least one), `truth` (what the ground truth is), optional `title`, `n_cells`, `notes` |
| `metrics` | list | section 3 |
| `resources` | list | runtime and memory per tool and dataset: `tool`, `dataset` (or `"pooled"`), `wall_s`, `max_rss_gb`, `threads`, optional `cpu_h`, `node`, `notes` |
| `figures` | list (optional) | section 4 |
| `artifacts` | list (optional, but needed by the notebook) | section 5 |
| `code` | list | `path`, `url` (GitHub `blob/<sha>/...` or `tree/<sha>/...`, pinned to a commit), optional `role` ("implementation", "harness", "metric") |
| `reproduce` | object | `module` (repo path of a Python file), `function` (callable with signature `compute(artifact_dir: Path) -> dict`, returning a capability document), optional `laptop_minutes`, `clipper_command` |
| `caveats` | list of strings (optional) | anything a careful reader should know. The index counts them. Do not hide a failure here: a metric that loses must be a failing metric |

## 3. Metrics and pass rules

```json
{
  "id": "per_cell_accuracy", "name": "Per-cell sex accuracy", "unit": "fraction",
  "category": "accuracy", "dataset": "lcl_1kg_pool", "direction": "higher",
  "singlet": {"value": 0.991, "ci": [0.987, 0.994]},
  "competitors": [{"tool": "cellXY", "value": 0.962, "ci": [0.955, 0.968]},
                  {"tool": "xist-chrY-threshold", "value": 0.948}],
  "rule": {"type": "match_or_beat", "against": "best", "tolerance": {"abs": 0.005},
           "rationale": "0.005 = half-width of the bootstrap 95% CI of the difference"},
  "pass": "pass",
  "notes": "optional"
}
```

- `category` is one of `accuracy`, `agreement`, `coverage`, `resources`, `robustness`.
- `dataset` is a dataset id from `datasets`, or `"pooled"`.
- `direction` is `higher`, `lower` or `none`. `none` is only valid with an equivalence rule.
- `singlet.value` and the competitor values are finite numbers, or `null` while incomplete. A final document has no
  null Singlet values. `ci` is optional.
- A competitor value from a truth tool is allowed: for example, the authors' count for an equivalence target.
- **`pass` is computed, never typed by hand.** Call `contract.finalize(doc)`; `validate` recomputes it and rejects a
  mismatch.

| `rule.type` | passes when | extra fields |
|---|---|---|
| `match_or_beat` | higher is better: s >= r - tol(r); lower is better: s <= r + tol(r). r is the best competitor value (`against: "best"`, the default), or each value of the tools listed in `against` | `against`, optional `tolerance` |
| `threshold` | s >= value (higher is better) or s <= value (lower is better). For truth-only metrics with no competitor | `value`, `rationale` (where the number comes from) |
| `equivalence` | \|s - t\| <= tol(t). t is a number or the value of the tool named in `target` | `target`, `tolerance` |
| `informational` | never gates; status `na`. **Not allowed when competitor values are present**, so a comparison cannot be published as "informational" to avoid a fail | |

The tolerance is `{"abs": a}` and/or `{"rel": r}`; when both are given, the larger slack applies. Any non-zero tolerance
needs a `rationale` that says why that margin counts as a match. Good rationales are measured noise: the bootstrap CI of
the difference, run-to-run variation of the competitor itself, or the competitor-vs-competitor disagreement on the same
data. "Looks close" is not a rationale.

**Capability status** (`contract.capability_status`):

| status | when |
|---|---|
| `pass` | `status: final`, at least one gating metric, and every gating metric passes |
| `fail` | any gating metric fails |
| `incomplete` | otherwise: a `na` value, or a draft document |

Runtime and memory always go in `resources`. They gate only if the owner also publishes them as metrics with category
`resources`. This choice is deliberate: a speed claim should be stated, not implied by a table.

## 4. Figures

The website renders figures from data, so every figure carries its own numbers:

```json
{"id": "sex_accuracy_by_dataset", "title": "Per-cell accuracy by dataset", "kind": "grouped_bar",
 "caption": "...", "x": {"label": "dataset", "categories": ["lcl_1kg_pool", "kang2018_ctrl"]},
 "y": {"label": "accuracy", "unit": "fraction", "scale": "linear", "min": 0, "max": 1},
 "series": [{"name": "Singlet", "tool": "singlet", "x": ["lcl_1kg_pool", "kang2018_ctrl"], "y": [0.991, 0.987],
             "err_lo": [0.987, 0.98], "err_hi": [0.994, 0.99]}]}
```

- `kind`: `bar`, `grouped_bar`, `scatter`, `line`, `box`, `histogram`, `heatmap` (`rows`, `cols`, `z`) or `table`
  (`columns`, `rows`).
- `series[].tool` should match a tool name, so the site can colour each tool the same way on every page; Singlet is
  always tool role `singlet`.
- Inline series have at most 5,000 points. Larger data goes in `data_file`, a path relative to `results/`
  (`results/data/<capability>/<figure>.csv` or `.json`), with optional `x`, `y` column names.
- Optional: `x.scale` / `y.scale` (`linear` or `log`), `reference_lines` [{`axis`, `value`, `label`}], `highlight`
  (a tool name).

## 5. Artifacts and reproduction

The notebook (`bench/public/notebook/singlet_benchmarks.ipynb`) regenerates every metric and figure. For each capability:

1. It downloads the `artifacts`: small per-cell tables of Singlet's output and every competitor's output, plus truth,
   each with `name`, `url`, `sha256`, `bytes` and `kind` (`singlet_output`, `competitor_output`, `truth`, `derived`),
   and optional `dataset`. Artifacts are compact: CSV, TSV or parquet, never BAM or FASTQ. A final document needs
   `sha256` on every artifact.
2. It calls `reproduce.module:function(artifact_dir)`, which returns a capability document. This must be the same
   function the harness used to write the published file, so the published numbers and the notebook cannot drift apart.
3. It checks the result with `contract.diff(published, recomputed)` and re-draws the figures.

Artifact URLs: until the release bucket exists, artifacts live on Clipper under
`$WORK/bench-public/artifacts/<capability>/` and URLs are written as
`https://data.singlet.bio/benchmarking/1.0.0/<capability>/<file>`. Uploading them is a separate, approved R2 write.
The notebook also accepts a local directory (`ARTIFACT_ROOT`).

## 6. The index

`python bench/public/contract.py index bench/public/results` writes `index.json`:

```json
{"schema": "singlet.benchmark.index", "schema_version": "1.0.0", "generated_at": "...",
 "singlet": [{"commit": "...", "version": "1.0.0"}], "overall": "incomplete",
 "n_capabilities": 22, "n_pass": 0,
 "capabilities": [{"capability": "chromosomal-sex", "title": "...", "file": "chromosomal-sex.json", "sha256": "...",
                   "owner": "...", "doc_status": "final", "valid": true, "status": "pass",
                   "n_metrics": 9, "n_pass": 9, "n_fail": 0, "n_na": 0, "n_caveats": 0, "conclusion": "..."}]}
```

- Every registered capability appears in the index. One without a file is listed as `missing`, and one whose document
  fails validation as `invalid`.
- `overall` is `pass` only when every capability passes.
- The index lists every Singlet commit seen. A final release should have exactly one.

## 7. Rules of the program

- **Same inputs for every tool:** the same FASTQs, the same reference (10x 2024-A GRCh38 / GRCm39, GENCODE v44 / M33),
  the same cells where a metric is per-cell (state which set), and the same threads and memory for timing.
- **Competitors run at their documented defaults** or at their authors' recommended settings for that data type. Their
  exact command lines go in `tools[].params`.
- **No tuning on the test truth.** A Singlet parameter chosen while looking at a cohort dataset's truth makes that
  dataset development data. Say so in `caveats`, or score on a held-out dataset.
- **Private data stays private.** Genotypes, per-site allele counts and donor SNPs never appear in a document or an
  artifact. Only summaries do: accuracy, counts, concordance.
- **Public naming:** the release is Singlet 1.0.0.
